# 0.5.0：多品种过滤与目标后缀自动匹配

本版移除执行器对单一 `XAUUSDp` 的限制。每条订阅分别设置源品种掩码，并可自动查找跟单账号可交易的同基础品种。**多个候选时报冲突，不优先选择同名品种，也不自动选择第一个。**

## 如何设置

1. 插件参数 `AllowedSymbol` 设置为 `*`。新安装默认值为 `*`；已有插件保留之前的参数，需将 `XAUUSDp` 改成 `*`，停用并重新启用插件使参数生效。
2. 管理界面点击“读取生效配置”，在“常规”页双击需要修改的关系。
3. “源品种掩码”填写 `*`，勾选“自动匹配目标品种后缀”。“源后缀”可以留空；若源品种都是 `XAUUSDp`、`EURUSDp` 这类命名，也可明确填写 `p`。
4. 确定写入草稿，暂停新仓，等待已提交请求完成，再“应用配置”。老仓无需平仓。读回确认后恢复新仓。

旧配置升级后保留“同名品种”行为；需要在各关系中主动勾选自动匹配。新增关系默认勾选自动匹配，但关系本身仍默认停用。保存到文件只保存草稿，应用成功后才影响执行器。

## 源品种掩码

支持 MetaQuotes 的 `*`、逗号分隔和 `!` 排除形式，参见 [MetaQuotes 品种过滤文档](https://www.mql5.com/en/docs/python_metatrader5/mt5symbolsget_py)。这里按完整源品种名称匹配，区分大小写；点号是普通字符。掩码不是 PCRE 正则，`?`、`[]` 不提供正则语义。

| 掩码 | 范围 |
| --- | --- |
| `*` | 所有源品种名称 |
| `XAUUSD*` | `XAUUSD` 以及带不同后缀的名称 |
| `EURUSD*,GBPUSD*` | 两组源品种 |
| `*,!XAUUSD*` | 包含全部，再排除 `XAUUSD` 这一组 |
| `XAUUSDp` | 只匹配这个完整名称 |

插件 `AllowedSymbol` 与订阅的“源品种掩码”必须同时匹配才接收新仓。掩码最长 4,096 个 UTF-8 字节、最多 64 项，每项最多 255 字节；需要至少一个包含条件。常用写法为先包含、后排除。关闭或修改掩码不会停止已在管仓位的平仓处理。

## 自动匹配规则

以源 `XAUUSDp`、基础品种 `XAUUSD` 为例，以下候选均假定满足目标账号权限、合约规格及执行方式要求：

| 目标账号可交易的同基础品种 | 结果 |
| --- | --- |
| 只有 `XAUUSD.p` | 跟随到 `XAUUSD.p` |
| 只有 `XAUUSDp` | 跟随到 `XAUUSDp` |
| 同时有 `XAUUSDp`、`XAUUSD.p` | 显示“品种匹配冲突”，该映射不下单 |
| 没有合适候选 | 显示无可交易且合约一致的目标品种，该映射不下单 |

不同跟单账号分别解析，所以一个源仓可以同时对应账号 A 的 `XAUUSDp` 和账号 B 的 `XAUUSD.p`。

基础品种识别顺序：

1. 填写了“源后缀”时，精确去掉这个后缀；源名称不带该后缀则报告不匹配。`p` 和 `.p` 不等价。
2. 留空时优先使用 SDK 的 `Basis`，要求它是源名称的真前缀。
3. 再尝试 `CurrencyBase + CurrencyProfit`，例如 `XAU` + `USD`、`EUR` + `USD`，仍要求是名称前缀。
4. 无法推导时用完整源名作基础名称。指数、股票等非货币对若缺少可用元数据，需要明确填写源后缀，避免猜错基础品种。

目标名称须以基础名称开头，剩余部分作为目标后缀。候选读取目标账号所属组的生效配置，并检查交易方向、Market Execution、IOC/FOK、市价单权限、手数最小值/最大值/步长。源与目标的合约大小、计算方式、报价位数、基础/利润/保证金币种、ISIN、起止时间和期权字段也须一致。本版不自动换算不同合约大小，不将 `GOLD` 等别名自动等同于 `XAUUSD`。

`*` 放开名称过滤，但账户仍要求同服、USD、Hedging；执行方式和服务器交易检查继续有效。实际能否成交还取决于交易时段、价格、资金及服务器检查，不保证候选一定成交。

## 平仓、重启与冲突处理

- 每笔映射保存源品种、实际目标品种及开仓时的配置。目标品种与交易请求一起落盘成功后才发送下单请求。
- 部分平仓、全平和重启恢复直接使用保存的目标品种，不重新选择后缀。修改订阅只影响之后接收的新仓。
- 运行页“源→目标品种”会显示如 `XAUUSDp → XAUUSD.p`；冲突候选显示在原因中，也记入执行器日志。
- 无候选或多候选会保留待核对记录，其他正常映射继续运行。只有这种已确认没有提交请求、没有目标仓位的品种冲突，才允许暂停后直接修改配置并恢复。成交未知等异常仍需核对。
- 解决冲突后只接收之后的新仓，原先跳过的源仓不会自动补跟。若要自动匹配成功，需要让目标账号只有一个符合条件的候选；也可以针对需要保持同名交易的订阅关闭自动匹配。
- 每轮规划共享一次服务器品种目录，同组同基础名称共享该轮的生效候选，下一轮重新读取。已有平仓请求先提交，再处理新仓的品种查找；不是对每个目标账号重复扫描整份目录。

## 账本与容量

本版写入 **journal schema 5**，向后读取 schema 1–4。旧映射按原源品种恢复目标品种，保持旧版同名绑定。旧账本身份中的 `;symbol=XAUUSDp` 兼容读取；服务器、API 和应用 ID 仍须匹配。修改过滤范围无需删除账本。

配置新增字段 `symbol_mask`、`auto_symbol`、`source_suffix`，使用配置 schema 3；旧 schema 2 默认全部源名称、同名目标，不自动启用后缀匹配。全默认字段导出时仍可使用 schema 2。示例见 [多品种配置示例](../config/copier.symbol-routing.example.json)，示例账户是占位值且全部停用。

继续支持 **10,000 条同时在管映射**。新仓快照保护 16 MiB，单快照硬上限 32 MiB，主文件检查点阈值 64 MiB，磁盘余量保护 256 MiB。每个待新增映射按 8 KiB 预留空间，覆盖最多 4 KiB 的冻结掩码及品种、规则、请求字段；超长规则或大量异常证据可能先触发字节保护。容量暂停只阻止新仓，已有仓位继续管理。确认全平后清理完整映射及已完成请求，未决/待核对证据保留。

## Windows 构建与更新

在解压后的 `mt-plugins` 目录，用 x64 Native Tools 命令行运行。把下面 SDK 路径替换为实际路径，其下须有 `Include\MT5APIServer.h`（API 6182）；源码包不包含授权 SDK。

```cmd
scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\MT5ServerAPI" -BuildDirectory build-windows-0.5.0
```

必须看到 **5/5 CTest 全部通过**。0.4.6 的 `ActiveConfigRealJournal` 检查点发布失败修复已包含在本版，仍需在你的 Windows 上通过这一项；失败时不要使用旧目录产物替代新构建。

可在 Windows 进一步运行实际临时文件的容量模拟（不连接 MT5、不下真实订单）：

```cmd
build-windows-0.5.0\Release\tradecopier_execution_tests.exe --capacity-soak
```

产物在 `build-windows-0.5.0\package-executor`：

1. 暂停新仓，等待未决请求完成；停用插件后备份当前配置、账本及程序。
2. 一起更新 `TradeCopierExecutor.dll`、`TradeCopierManager.exe`、`TradeCopierJournal.exe`。
3. 保留原 `JournalPath` 和原账本，将 `AllowedSymbol` 设为 `*`，重新启用插件、连接新版管理界面。
4. 读取生效配置、为需要的订阅开启自动匹配，按上文流程应用并恢复。

新 schema 5 写入后旧版不能读取，不可直接用旧程序或旧账本覆盖降级。已有异常现场不会因为升级而自动解除 HALTED，也不会自动补发交易。

## 验证范围

本地覆盖掩码、候选冲突、无候选、不同账号的 `p` / `.p` 选择、目标绑定落盘失败不下单、部分/全部平仓、带仓修改、实际文件重启与旧账本兼容。Windows EXE 交叉编译及 SDK 辅助语法检查通过；**尚未完成本版 Windows MSVC / NTFS / Demo 实机验收**。各组结果及容量模拟数据见 [构建验证记录](windows-build-validation.md)。

Demo 验收重点：同一信号源跟到两个不同后缀账号；修改规则后老仓按原品种平仓；目标同时开放两个合适后缀时不下单且显示冲突；重新启用插件后仍能按已保存品种平仓。所有交易验收由你在测试环境操作。
