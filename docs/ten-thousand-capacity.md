# 0.4.6：同时在管 10,000 条映射

> 当前 0.5.1 的调度、增量账本格式及复跑说明见 [0.5.1 文档](throughput-0.5.1.md)。下文保留该历史版本的验证记录。


> **当前版本 0.5.0**：新增多品种掩码与自动后缀匹配，账本写入 schema 5，保留 10,000 条容量与检查点修复。当前构建、设置和兼容说明以 [0.5.0 多品种说明](symbol-routing.md) 为准；下文版本记录用于历史参考。

> **Windows 构建更新**：0.4.6 已在用户本机测试发现检查点替换失败，改用 [0.4.7 修复包与构建步骤](windows-checkpoint-fix.md)；下文旧版本命令仅供历史参考。

按本轮确认的需求，将新仓准入上限从 4,096 调整为 **10,000 条同时在管映射**。一笔源仓跟随到 1,000 个目标账号，会产生 1,000 条映射；10 笔这样的源仓合计 10,000 条。该数字不是账号数、历史成交数或并发下单数。

## 容量设置

| 项目 | 0.4.5 | 0.4.6 |
| --- | --- | --- |
| 新仓准入映射上限 | 4,096 | **10,000** |
| 新仓快照容量保护 | 8 MiB | **16 MiB** |
| 单次完整快照硬上限 | 16 MiB | **32 MiB** |
| 主账本检查点阈值 | 32 MiB | **64 MiB** |
| 新仓要求的磁盘余量 | 128 MiB | **256 MiB** |
| 不同账号同时等待成交 | 32 笔 | 32 笔 |
| 配置订阅关系 | 最多 1,000 条 | 最多 1,000 条 |

单个新信号对应的全部订阅必须一起通过容量检查；不能将总映射数增加到 10,001 或以上。达到 10,000 条本身不会停止跟单。下一笔会超限的新信号触发新仓暂停，已建立的映射继续跟随部分平仓和全平。

快照保护检查当前实际字节数，并对每条新增映射另外预留 4 KiB。正常的 10,000 条映射已纳入文件测试；极端的成交明细或异常记录仍可能先触发字节保护，不能把“10,000 条”理解为任何大小的记录都能无条件容纳。暂停后由管理员检查并恢复，不自动补跟暂停期间的新仓。

主文件的 64 MiB 是检查点更新阈值，不是到达后停止的上限。下一帧将越过阈值时，先将最新状态刷盘到临时文件，再替换主文件；替换期间还需要一份最新快照的空间。确认全平后继续物理清理完整历史，不新建历史归档。磁盘真实写满、损坏或异常数据超出格式限制仍需停止并保留证据。

## 大仓量下的处理

- 账本读取、引擎恢复、管理接口共用 10,000 条映射上限，界面总数仍准确；展示列表保持最多 200 行，避免每次刷新传输全部明细。
- 同一源仓对应多个订阅时，重启核对共用本轮的源历史查询结果；每个目标仓位仍单独校验实际余量。
- 空闲清理先判断有没有可清理记录，没有时不再深复制全部在管状态。
- CRC 校验改为等价查表计算，兼容原账本校验值。

持久化仍采用完整快照。大批成交时的磁盘写入成本、SDK 历史查询和服务器成交处理仍需在实际 Windows / Demo 上测量；本版没有宣称 10,000 笔仓位能瞬间一起开平。32 笔并发等待与同时持有 10,000 条映射是不同的限制。

## 构建与升级

源码包：`out/mt5-trade-copier-0.4.6-capacity-10000-source.zip`，不含 SDK、账号运行数据或可直接部署的 MSVC DLL。

```bat
cd /d D:\work\mt-plugins
scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\MT5ServerAPI" -BuildDirectory build-windows-0.4.6
```

SDK 路径替换为实际 Server API 6182 SDK 根目录，内含 `Include\MT5APIServer.h`。

停用插件后备份并保留现有主账本、`.lock`、配置和旧程序，同步更新：

- `TradeCopierExecutor.dll`
- `TradeCopierManager.exe`
- `TradeCopierJournal.exe`

格式仍为 schema 4，但扩大后的快照可能超过 0.4.5 的读取限制，三个程序应统一使用 0.4.6，不建议回退旧程序。启动日志应包含 `(0.4.6)`、`max-managed-mappings=10000` 和 `checkpoint=64MiB`。

原来的 HALTED / 未决请求仍需核对，不会因扩容自动解除，也不会自动补平遗留仓位。文件恢复规则继续见 [运行账本说明](live-state-journal.md)。

## 10,000 条专项验证

```bat
build-windows-0.4.6\Release\tradecopier_execution_tests.exe --capacity-soak
```

该测试只使用模拟交易端口和临时账本，流程为：

1. 从真实文件恢复 9,000 条已确认映射，再经过正常准入、持久化和提交确认流程增加 1,000 条。
2. 核对管理接口显示在管 10,000 条，记录列表按 200 行截断。
3. 再增加新信号，确认暂停新仓、原有 10,000 条映射不受损。
4. 暂停期间先完成 1,000 笔部分平仓，复制实际账本验证 10,000 条持仓重启恢复、无重复提交，再完成全部 10,000 笔最终平仓。
5. 检查全部目标余量为零、账本不超过检查点阈值、已结束记录被清理、请求编号保持递增、最终账本重载一致。

实际测试结果见 [构建验证记录](windows-build-validation.md)。此模拟验证容量与执行逻辑，不等于 Windows 文件系统、MSVC DLL 或真实成交性能验收。
