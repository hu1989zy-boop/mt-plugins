# 0.4.2：带仓修改订阅，老仓保留开仓规则

> 0.6.0 已更新运行策略：按映射隔离异常，不自动全局终止；订阅可运行中加入，退出会关闭该关系仓位。新的行为及升级步骤以 [0.6.0 说明](live-subscriptions-0.6.0.md) 为准。

> 0.4.3 包含本页功能，并增加不同跟单账号并行等待成交与批次刷盘。最新构建 / 部署使用 [0.4.3 说明](account-pipeline.md)。

## 行为

可以修改已有持仓的订阅，无需平仓。每笔映射在接收源新仓时保存一份独立的开仓规则，包含关系 ID、源账号、目标账号、手数模式及参数。配置提交只影响之后接收的新仓，不改写老映射或其交易请求。

例如 `50001 → 50002` 从 **1 倍改为 0.5 倍**：

| 仓位 | 源开仓 | 目标开仓 | 源平一半时目标减仓 |
| --- | --- | --- | --- |
| 修改前建立的映射 | 0.04 手 | 0.04 手 | 0.02 手 |
| 修改后恢复跟随、再新开的映射 | 0.04 手 | 0.02 手 | 0.01 手 |

以上示例假设没有手动减仓，且数量满足品种步长。三种模式均延续当前平仓算法：按“本次源平仓量 / 平仓前源剩余量”减少目标**实际剩余量**，源全平则关闭对应目标余量。不会用修改后的倍率重新计算老仓目标量，也不会补仓或立即调仓。净值模式已记录的开仓净值和成交量继续保留，平仓不重新查询净值来重算开仓量。

- 修改模式或参数：老仓使用自己的开仓规则，新源仓使用新配置。多次修改可同时存在多批不同规则的持仓。
- 修改账号：老映射仍管理原源仓和原跟单账户的原目标票号。界面保留“换账号生成新关系 ID、默认停用”的行为，核对后勾选启用再应用。
- 停用 / 删除订阅：停止该订阅接收新仓，已建立的映射继续管理到结束。当前仍要求整个配置全局启用且至少一条关系启用；暂停全部新仓使用“暂停新仓跟随”。
- 暂停和应用配置期间，老仓仍继续跟随平仓。恢复只接收恢复后新开的源仓，暂停期间开的仓位不会补跟。
- 运行状态的“开仓规则 / 原因”显示每笔映射实际保存的模式与参数，跟单账号也来自该映射。新老规则不会混用。

## 操作步骤

1. 点击“暂停新仓跟随”，等待正在提交的请求确认。**不要求平掉剩余持仓。**
2. “读取生效配置”，编辑相应订阅并在编辑弹窗中确定。
3. 点击“应用配置”。仍会校验关系图、账户、品种和账本版本；未决交易、待核对、HALTED 或磁盘异常不能绕过。
4. 确认配置应用成功，检查新配置及老映射，然后“恢复新仓跟随”。保存 JSON 只保存草稿，不代替应用配置。

## 账本与恢复

- 写入原来的 `executor-two-to-one.journal`，不用新建文件。每笔映射只增加自己的单条规则快照，不复制整份配置；老映射、票号、余量、已处理平仓、请求编号全部保留。
- 二进制账本升级为 **schema 3**；配置 JSON 仍为 schema 2，本机管理协议仍为 v1。
- 可以读取 schema 1 / 2 旧账本。旧格式在管映射从当时生效配置恢复开仓规则，在第一次新快照中持久化。旧版已经结束的映射没有可靠的历史参数时显示“未记录开仓规则”，不会冒用当前配置。
- 新格式恢复时检查规则快照不被后续配置或交易记录改写。重启、停用 / 删除旧订阅后，老映射仍用自己的账户及规则恢复。
- **旧版 DLL 和账本检查器不能读取 schema 3。** 同时更新三个程序。第一次写入新格式后不能直接换回旧程序，也不能用旧备份覆盖已继续交易的当前账本。
- 原先的全量快照追加、256 MiB 账本上限、16 MiB 单记录上限及历史容量限制仍存在。本次没有实现归档 / 压缩或改变刷盘机制。

## Windows 部署

1. 将 `mt5-trade-copier-0.4.2-frozen-rules-source.zip` 的 `mt-plugins` 内容合并到现有源码目录，保留自己的 `vendor\mt5-sdk`。源码包不包含 SDK、服务器配置、账本或部署二进制。
2. 在 Windows VS x64 Native Tools Command Prompt 构建：

   ```cmd
   cd /d "D:\work\mt-plugins"
   scripts\build-windows.cmd -Executor -BuildDirectory build-windows-0.4.2
   ```

   SDK 不在默认目录时添加 `-SdkRoot "实际 SDK 根目录"`。必须构建执行器，不能只使用 `-UiOnly`。确认构建及测试通过，管道运行测试需要管理员权限。
3. 在 Demo 维护窗口暂停新仓、等待未决请求确认；记录原映射，停用插件，等待 `plugin shutdown finished`，备份原 DLL、两个 EXE 及账本。共用 DLL 的实例需要全部卸载后替换。
4. 从 `build-windows-0.4.2\package-executor` 更新：

   | 文件 | 当前 Demo 位置 |
   | --- | --- |
   | `TradeCopierExecutor.dll` | `D:\MT5 Platform\Demo MainTrade\plugins\TradeCopier\TradeCopierExecutor.dll` |
   | `TradeCopierManager.exe` | `D:\MT5Copier\TradeCopierManager.exe` |
   | `TradeCopierJournal.exe` | `D:\MT5Copier\TradeCopierJournal.exe` |

   保留插件参数以及 `D:\MT5Copier\runtime\executor-two-to-one.journal`，不清空运行账本。
5. 重新启用插件，管理通道启动日志应包含 `per-mapping opening rules supported (0.4.2)`。以管理员身份连接服务器 `1` / 应用 `3101`，核对原映射、余量及暂停状态，再按前述步骤修改订阅。

无需为本功能平掉老仓。升级卸载期间执行器无法管理平仓；如果源仓在停机期间变化，现有重启保护仍可能进入待核对。应安排 Demo 维护窗口，不能将“保存开仓规则”理解为停机期间自动补处理交易。

## 验证与 Demo 验收

本地自动化覆盖：三种手数模式，改模式 / 参数后新旧仓并存，老仓部分平仓，账号调整，多次修改，停用和删除，重启恢复原账户及票号，真实文件账本重载，schema 1 / 2 升级、混合格式重放及降级拒绝，非法快照 / 历史变更拒绝，未决请求、过期版本、落盘失败和确认丢失保护。刷新调度测试仍保留。

构建验证记录见 [Windows 构建验证](windows-build-validation.md)。本地 ASan / UBSan、Windows EXE 交叉编译和 SDK 辅助语法检查不等于 Windows MSVC 构建或 Demo 加载；**0.4.2 尚待 Demo 实机验证**。

Demo 建议先用一条订阅验证上表：保留旧 1 倍仓位，暂停并改为 0.5 倍应用，确认应用不主动调仓；恢复后再开新源仓；分别部分 / 全部平仓，核对两笔目标票号和减仓量。然后验证带仓正常停用 / 启用恢复，以及固定手数、净值模式和删除订阅后的老仓管理。
