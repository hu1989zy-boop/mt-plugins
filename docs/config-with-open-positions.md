# 0.4.1：有持仓时新增订阅（2026-09-17）

> 0.6.0 已更新运行策略：按映射隔离异常，不自动全局终止；订阅可运行中加入，退出会关闭该关系仓位。新的行为及升级步骤以 [0.6.0 说明](live-subscriptions-0.6.0.md) 为准。

> 历史说明。0.4.2 已进一步支持带仓修改、停用和删除原订阅，老仓保留开仓规则；最新部署步骤见 [0.4.2 说明](frozen-opening-rules.md)。下文的“活动原关系不能修改”限制仅针对 0.4.1。

## 调整后的行为

**新增订阅不再要求原有持仓全部平仓。** 先暂停新仓，保留仍在管理持仓的原关系，添加订阅并应用，检查后恢复新仓跟随。原有持仓在暂停和配置应用之后继续按原关系管理，包括部分和全部平仓。

| 操作 | 0.4.1 行为 |
| --- | --- |
| 原关系有正常持仓，新增另一条订阅 | 允许应用，无需平仓 |
| 为已有信号源新增另一个跟单账号 | 允许；原源仓不会补跟，新源仓按各关系独立跟随 |
| 为已有跟单账号新增另一个信号源 | 允许；原有映射、目标票号及余量保留 |
| 修改、停用或删除没有在管持仓的关系 | 允许，仍校验关系图及账号 / 品种 |
| 修改、停用、删除或换 ID 的关系仍有在管持仓 | 拒绝，并指出具体关系 ID；应用其他新增订阅时保留这条原关系即可 |
| 开仓或平仓请求正在确认 | 等待成交回报完成后再应用；不要求把剩余持仓平掉 |
| HALTED、待核对映射、未确认请求、账本异常 | 继续拒绝应用，不绕过异常处理 |

有持仓的关系必须保留原 ID、源账号、跟单账号、启用状态、手数模式和参数。`1` 与 `1.000` 等数值等价的参数表示视为相同设置。检查使用完整账本，不依赖界面最多显示的 200 行。

应用成功后仍保持新仓暂停。恢复时重新采集基线，仅跟随恢复后真正新开的源仓；旧仓、暂停期间出现的仓位不会补跟。

## 原因与实现

此前执行器的 `ApplyBlockReason()` 统一要求所有映射终结；账本读取器也只接受这种配置切换。因此只改管理界面按钮不能解决问题。

本版同时调整执行器校验和账本恢复：

- 正常 Active 映射不再构成全局应用阻碍；具体草稿需保留这些映射对应的原关系设置。
- 在账户 / 品种校验和监听集合切换之前先验证关系兼容性，执行器提交前再次检查。
- 配置仍以一次同步落盘快照作为提交点。映射、源 / 目标余量、已处理的源平仓、成交及请求编号全部保留。
- 账本恢复接受兼容的带仓配置变更，并检查除配置、版本及开仓基线外的执行记录均未改变；校验和正确但篡改历史的配置切换仍会拒绝读取。
- 新旧关系都由原来的单执行线程处理；没有新增自动平仓、历史补跟或失败重发。

## 版本及账本兼容

- 管理协议仍为 v1；配置 JSON 及账本二进制 schema 2 的字段格式不变。可继续加载原 0.4.0 账本，不需要重建或清空。
- **必须更新 `TradeCopierExecutor.dll`。** 仅更新管理 EXE，旧执行器仍会要求全部映射结束。
- **同时更新 `TradeCopierJournal.exe`。** 0.4.0 的旧执行器 / 旧检查器会把新增的“带仓配置切换”记录判为无效，即使二进制 schema 没变。产生这类记录后不能直接换回旧程序读取当前账本。
- 升级前保留程序及账本副本。升级后产生新交易或配置变更时，不要用旧备份覆盖当前账本。

## Windows 更新步骤

1. 把 `mt5-trade-copier-0.4.1-active-config-source.zip` 中 `mt-plugins` 的内容合并到现有工程 `D:\work\mt-plugins`，保留原 `vendor\mt5-sdk`（Server API 6182）。源码包不含 SDK、运行账本或本机配置。
2. 先在 VS x64 Native Tools Command Prompt 构建和运行测试：

   ```cmd
   cd /d "D:\work\mt-plugins"
   scripts\build-windows.cmd -Executor -BuildDirectory build-windows-0.4.1
   ```

   SDK 位于其他目录时追加 `-SdkRoot "实际 SDK 根目录"`。本次需要构建执行器，不能使用 `-UiOnly`。等待 `Build and tests passed`；Windows 管道测试需要管理员权限，否则会跳过。
3. 在 Demo 维护窗口暂停新仓，等待正在提交的请求确认完成。记录现有持仓 / 映射，然后停用 `TradeCopierExecutor`，等待 `plugin shutdown finished`，备份 DLL、两个 EXE 及原账本。多实例共用 DLL 时需全部卸载该 DLL 后才能替换。
4. 从 `build-windows-0.4.1\package-executor` 替换：

   | 新文件 | 当前 Demo 位置 |
   | --- | --- |
   | TradeCopierExecutor.dll | `D:\MT5 Platform\Demo MainTrade\plugins\TradeCopier\TradeCopierExecutor.dll` |
   | TradeCopierManager.exe | `D:\MT5Copier\TradeCopierManager.exe` |
   | TradeCopierJournal.exe | `D:\MT5Copier\TradeCopierJournal.exe` |

   保留插件参数和 `D:\MT5Copier\runtime\executor-two-to-one.journal`。DLL 仍被锁定时，按该 Demo 服务的维护流程完成卸载后再替换。
5. 重新启用插件，日志应包含：

   ```text
   compatible config apply supported (0.4.1)
   ```

   界面信息页版本为 0.4.1。以管理员身份连接服务器 `1` / 应用 `3101`，读取生效配置，确认原映射、目标票号、余量及暂停状态。

无需为这项功能先平掉旧仓。不过，执行器卸载期间无法管理平仓；现有重启保护会检查源历史是否变化，若期间发生交易变化可能进入待核对。选择 Demo 维护窗口完成替换。

## 新增订阅的日常步骤

1. 点击“暂停新仓跟随”。已有持仓继续管理。
2. 常规页“读取生效配置”，保留有持仓的原关系。
3. 添加新关系，填写账号、手数及启用状态，点击弹窗“确定”。
4. 点击“应用配置”。如提示正在确认交易，等待该请求确认、刷新后再应用；若版本已变化，重新检查当前状态后提交。
5. 成功提示应包含“已有持仓继续管理”。读取生效配置核对，再恢复新仓跟随。

## 验证情况

已通过 ASan / UBSan 下四组 CTest，以及 Windows 管理 EXE、账本工具和测试 EXE 的 LLVM-MinGW 交叉编译。使用原始 API 6182 头文件的服务端辅助语法检查通过；这不等于 MSVC / DLL ABI 验证。

新增自动化场景包括：带部分持仓新增一对多 / 多对一订阅；原仓在应用后继续分批及全部平仓；新增关系不补跟旧仓；恢复后独立手数；三种手数模式和 64 位 ID；活动关系不兼容修改被拒绝；未决请求、过期版本和故障保护；提交前落盘失败 / 落盘后确认丢失；真实文件账本重启后继续原仓平仓；配置切换篡改历史时拒绝恢复。

**Windows MSVC 构建、Demo 加载及新行为的实机验收尚待完成。** 建议在 Demo 保留一笔原关系持仓完成新增订阅，确认应用本身不触发平仓，再验证原源仓正常部分 / 全部平仓时仍对应原目标票号，新关系只跟随恢复后的新源仓。
