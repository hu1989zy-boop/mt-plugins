# MT5 Server API DLL 与独立 Windows 管理界面

状态：SDK 已取得，按 Server API 6182 开发；用户提供独立 Windows 测试环境。业务核心、配置库和原生离线编辑器源码已实现，只读诊断 DLL 用于接入验证。真实开平仓、状态恢复与界面控制执行端仍未实现。

## 职责分工

| 组件 | 目标职责 |
| --- | --- |
| Server API DLL | 观察源交易、校验每条关系、计算数量、提交目标开平仓、核对实际成交、持久化状态 |
| Windows 管理界面 | 已实现原生本地关系编辑、配置导入导出和公式提示；配置应用、状态与日志展示需继续实现管理通道 |
| SDK 无关业务核心 | 校验关系、计算理论开仓与部分平仓数量；不调用 MT5，不拥有 Live 执行能力 |
| 配置与运行状态存储 | 保存版本化规则、每关系启用基线、源目标仓位关联、执行意图和真实结果 |

执行端加载在 MT5 服务端。独立界面只是管理客户端，不承担跟单循环；界面关闭后 DLL 应继续按已确认配置运行。此行为需要后续集成验证。

Administrator 参数列表截图是配置风格参考，不等于必须把自定义界面嵌入 Administrator，也不证明第三方插件的参数协议。当前不引用第三方 DLL、参数键或功能作为兼容目标。

## 配置结构与界面行为

`config/copier.example.json` 是当前离线编辑器可导入的逻辑样例，`relationships` 中每一行分别包含源账号、目标账号、手数模式与参数。同一目标可以出现于多行，同一源目标对不能重复。账号和十进制参数均为字符串；`relationship_id` 使用范围可校验的正数字字符串，与核心的 `uint64` ID 对接。严格 JSON 解析已实现，但尚未将配置应用到服务器。

三种模式分别展示对应字段：

- `multiplier`：`multiplier`。
- `equity_ratio`：`coefficient`，收到源开仓成交后、提交跟单前查询双方净值并冻结；分别记录源成交时间和双方查询时间。
- `fixed_lots`：`lots_per_source_trade`。

保存配置应先做整图校验，再提交一个版本；只有执行端确认应用后，界面才显示“已生效”。配置编辑中的值不能被标记为已在 Live 运行。关系 ID 在参数修改时保持稳定，既有仓位继续使用其开仓时的参数与映射；改变源或目标属于新关系，应建立新的 ID 和启用边界。

启停含义应在界面中明确：暂停新仓跟随仍管理既有映射，完全停止执行会中断同步且不自动平仓。对尚有在管仓位的关系，不能通过删除配置丢失其状态。

## Administrator 参数与本地配置

独立界面直接编辑结构化 JSON。SDK 的 `MTPluginParam` 默认值缓冲为 256 个宽字符，不适合把多对多大配置直接塞进默认参数；这不等于已经证明运行时所有参数具有同样的长度上限。

当前只读探针仅通过 `PluginCurrent` 读取 `WatchLogin` 与 `MaxEvents`，不读取跟单 JSON。正式配置通道仍需实现，不把第三方截图的 `Rules` 语法当成协议，也不向用户提供看似可粘贴即用的未实现导入格式。

## 界面与插件之间的通道

第一阶段已实现独立界面的本地配置编辑、导入和导出；未连接 MT5。配置写入服务端、状态读取和命令确认的通道尚未实现。已核实 `PluginCurrent` 是 DLL 内部接口，不能直接充当独立 EXE 的远程入口；管理通道还需定义访问范围、调用者验证、配置版本与响应状态。

不能直接承诺 Server API 为独立 EXE 提供远程读写，也不能假定 Administrator 提供任意 UI 扩展。如果确需配套 Manager SDK 作为管理通道，应另行核实 SDK 与权限；这不改变当前由 Server API DLL 执行跟单的架构。不预设为 Trade Server 增开 HTTP 端口。

管理通道中断时，界面应显示数据更新时间和离线状态；不能把本地按钮变化显示成服务端已执行。DLL 保持最后一个成功应用的配置，配置恢复失败则暂停新增交易并显示待核对状态。

## 运行状态与恢复

至少持久化：服务器身份、关系 ID、配置版本、每关系启用边界、源生命周期与目标仓位关联、人工干预状态、已处理事件、开仓净值样本、执行意图、未决请求及真实成交结果。

采用 SDK 支持的调度与线程模型，不能在服务器回调里执行不受控的慢任务。请求结果未知时先核对真实仓位和成交，不盲目重复下单。无法可靠关联时进入待核对状态，由界面明确显示原因。

重载不重新设定启用时间；关闭界面不清空状态。插件卸载或停止不会默认平掉客户仓位。重启后先核对既有状态，再接纳新仓，未完成核对不能显示正常执行。

## 实现边界

已有可视化交互原型和原生 Win32 离线编辑器源码；原生界面尚未在 Windows 运行验证。SDK 无关核心可测试规则与算术，只读探针可在构建后检查加载和成交回调；它们都不证明真实跟单执行、指定仓位关闭、崩溃恢复或实际目标成交已实现。

官方对 Server API 的定位见 [MetaTrader 5 券商端说明](https://www.metatrader5.com/en/brokers)。确切导出函数、生命周期与接口签名只能从匹配版本的 Server API SDK 核对。
