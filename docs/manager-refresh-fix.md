# 0.4.0 管理界面刷新修复（2026-09-16）

## 修复内容

原界面把每 2 秒的后台状态读取当作用户操作，因此“读取生效配置”“核对选中请求”“暂停/恢复新仓”等按钮会反复禁用。修复后：

- 后台状态读取期间，连接有效且快照未过期时，相关按钮保持可用；业务状态仍决定暂停、恢复、应用等按钮是否可用。
- 用户操作与后台读取使用同一条串行请求通道。若点击时后台请求还未返回，暂存一次操作，显示等待提示，完成刷新后提交；额外点击不会替换或重复提交已接受的操作。
- 暂存的只读核对固定使用点击时选中的请求 ID；应用配置固定使用确认时的配置内容。读取配置从等待开始锁定草稿编辑，避免返回后覆盖新编辑。
- 提交前再次检查连接目标、执行器进程会话及写命令的账本版本。断线、快照过期、执行器重启或状态变化时明确提示本次操作未发送，不自动重试写命令。
- 用户主动连接、读取配置、核对及写操作期间仍暂时禁用相关按钮，直到该操作完成；后台刷新本身不再造成周期性闪灰。超过 6 秒无新快照仍按过期处理。
- 重连成功后标明“连接已恢复”，先前连接错误显示为历史记录；普通自动刷新保留最近操作/只读核对结果。

此修复只涉及管理 EXE、客户端调度测试及构建配置，兼容当前 0.4.0 执行器的管理协议。账本容量、完整快照写入和归档问题属于后续存储工作，本包未改变执行器或账本格式。

## 更新到 Windows Demo

1. 下载 `mt5-trade-copier-0.4.0-manager-refresh-fix-source.zip`，将其中 `mt-plugins` 目录的内容合并到 `D:\work\mt-plugins`。包内为源码和示例配置，不含运行配置、运行账本或可部署二进制。
2. 在以管理员身份运行的 VS x64 Native Tools Command Prompt 中编译：

   ```cmd
   cd /d "D:\work\mt-plugins"
   scripts\build-windows.cmd -UiOnly -BuildDirectory build-windows-manager-refresh
   ```

   等待 `Build and tests passed`。独立构建目录保留已有执行器构建；本命令不需要 MetaTrader SDK，也不会安装文件或改变服务状态。Windows 管道测试需要提升权限，否则该项会跳过。

3. 关闭 `TradeCopierManager.exe`，备份原管理 EXE，将新文件：

   ```text
   D:\work\mt-plugins\build-windows-manager-refresh\package-ui\TradeCopierManager.exe
   ```

   复制到 `D:\MT5Copier\TradeCopierManager.exe`。本次只替换管理 EXE；执行器 DLL、MT5 服务、参数及原账本均继续使用当前版本。
4. 以管理员身份重新打开界面，连接服务器 1 / 应用 3101，再读取生效配置。

## Windows 交互验收

- 观察至少 10 秒：在快照持续更新且连接有效时，读取配置/只读核对按钮不再每两秒闪灰。当前“新仓已暂停”时暂停按钮持续禁用、恢复按钮可用，这是业务状态要求。
- 连续几次在自动刷新附近点击“核对选中请求（只读）”。应能接受一次操作并显示结果；暂存期间改变表格选择，不应改变该次核对的请求 ID。请求总数、账本版本和暂停状态不因只读核对改变。
- 点击“读取生效配置”应成功载入，后台等待期间草稿不可编辑；操作完成后恢复编辑。
- 若执行器被停用或重新启用，旧请求应报未发送或连接失败；连接恢复后旧错误明确标为历史，命令不自动重发。此项可结合后续维护窗口验证。
