本版继续处理 0.4.3 因账本达到 256 MiB 而停止跟随平仓的问题，替代 0.4.4 的自动历史归档方案。运行账本会清理已结束的映射，接近容量阈值时提前暂停新仓，已有仓位继续管理。

## 保留什么

- 保留在管仓位、冻结的开仓配置、候选交易、未决请求及待核对异常。
- 确认目标仓位已完全关闭且关联请求全部确认后，删除完整映射和请求记录；手动全平也按此规则清理。
- 仍有持仓的映射保留开仓证据、最近一次已确认平仓请求、未决请求及源平仓成交去重编号。部分平仓不会提前删除仓位映射。
- 短期仅保留“关系 ID / 源账号 / 源仓位 / 源开仓时间”去重标记；源开仓时间超过 30 秒窗口后可清理，并持久化不可回退的时间门槛。候选开仓还核对源仓第一笔成交时间，防止延迟回调重新跟随旧仓。
- 请求编号单独持久化并一直递增，不依赖保留记录数量；重启后不会复用编号。
- HALTED、未确认、被拒绝或待核对的记录保留，避免将异常当成已结束交易删除。

因此运行页不再提供完整已平仓历史；历史交易仍以 MT5 服务器记录为准。已清理请求不能再从管理界面执行只读核对。删除一行历史记录不会触发交易，也不会解除 HALTED。

## 文件大小与平仓空间

| 检查 | 当前阈值 | 处理 |
| --- | --- | --- |
| 新开仓后的在管映射数量 | 最多 10,000 条 | 超过时暂停新仓，整个新信号的订阅组不做部分接收 |
| 保留的请求记录数量 | 50,000 条提前保护 | 暂停新仓；正常平仓后清理记录 |
| 新开仓预估快照大小 | 16 MiB（每条新映射另预留 4 KiB） | 暂停新仓，保留余量处理成交确认及平仓 |
| 账本磁盘可用空间 | 低于 256 MiB，或无法检查 | 暂停新仓，显示原因 |
| 当前文件累积写入 | 下一帧将超过 64 MiB | 写入完整最新检查点并替换当前文件，不再追加历史 |
| 已结束记录清理 | 完成确认后的工作轮次 | 写入清理后的检查点，物理移除当前文件中的旧快照 |

10,000 指同时保留的映射，不是账号数量；32 仍是跨账号等待成交的并发请求上限。上述容量值是本版源码常量，不是新插件参数。

容量检查在接收新信号及提交候选新仓前执行；已有仓位平仓不受这项新仓检查拦截。触发后记录暂停原因，管理界面会显示“新仓因容量自动暂停”；条件改善后需要人工点击“恢复新仓跟随”，不会自动恢复或补跟暂停期间的开仓。

检查点通过同目录 `.checkpoint.tmp` 写入、刷盘，再替换主文件；整个过程持有稳定的 `.lock` 独占锁。正常运行中主文件不超过 64 MiB，替换时还需要一份最新快照的临时空间。空仓并经过去重窗口清理后，只保留配置、编号和恢复元数据，具体大小取决于配置及启用基线。

不再创建新的 `.archive` 历史目录。以前的归档、人工备份不会自动删除，不计入主文件的 64 MiB 上限，仍会占用磁盘。

### 保护边界

这解决的是历史记录无限增长导致触及文件上限的问题，不是无限容量保证。单个快照的 32 MiB 格式限制、旧文件读取的 256 MiB 限制仍保留。极端的在管数据、单笔仓位大量部分成交、外部程序耗尽磁盘、权限变化或磁盘损坏仍可能使持久化失败；失败时必须保留证据并停止新交易提交，不能假装保存成功继续下单。

中断留下的 `.checkpoint.tmp` 不会被当成已提交状态加载，也不会被覆盖；下一次检查点写入会拒绝该文件。应停止插件、备份主文件/锁/临时文件并核对后处理，不能直接用临时文件或旧归档覆盖主账本。

## 升级与现场未平仓问题

本版继续写入 **payload schema 4**，读取兼容 schema 1 / 2 / 3 / 4。扩大后的快照可能超过 0.4.5 的读取限制。一起更新 `TradeCopierExecutor.dll`、`TradeCopierManager.exe`、`TradeCopierJournal.exe`；写入新格式后不能直接降级旧程序。

1. 停止插件后，备份当前 DLL、三个程序、配置、主账本、`.lock`，以及存在的旧归档和临时文件。保留原账本路径。
2. 使用匹配的 Server API 6182 SDK，在 x64 Developer Command Prompt 构建：

   ```bat
   cd /d D:\work\mt-plugins
   scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\MT5ServerAPI" -BuildDirectory build-windows-0.4.6
   ```

   将示例 SDK 路径换成实际路径，其中应有 `Include\MT5APIServer.h`。源码包不包含 SDK。

3. 按构建输出的 package 目录同步替换 DLL 和两个 EXE。`JournalPath` 继续使用 `D:\MT5Copier\runtime\executor-two-to-one.journal`。
4. 查看启动日志中的 `(0.4.6)`、`live journal checkpoint=64MiB` 以及管理界面版本。核对实际账号持仓和在管/待核对/未决数量。

`.lock` 现在也保存账本已初始化标记，不可随意删除。主账本丢失或为空时会拒绝按新账本启动，防止重置编号和失去在管仓位。

**本版不会自动解除现场 HALTED，也不会自动补平之前遗留的 18 笔仓位。** 有未决请求时必须核对实际成交；保留原账本，不能靠删除账本或清空历史来恢复。

本地模拟覆盖平仓后物理清理、手动全平、部分平仓、延迟重复回调、时钟回退、稀疏编号重启、冻结开仓规则、批量请求索引重排、容量不足仍继续平仓、清理失败、损坏/丢失文件、旧 schema 迁移。
