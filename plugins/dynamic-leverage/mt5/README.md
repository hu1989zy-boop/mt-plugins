# MT5 动态杠杆插件

> 2026-10-14：账户杠杆写入已停用，当前正式 DLL 会拒绝启动旧执行流程。新需求是新仓使用新杠杆、旧仓保持原杠杆。以下是旧版构建与运行说明，其中部署启用和账户杠杆变化的步骤已失效。当前状态见 [新仓保证金实现](../docs/new-position-leverage.md)。

独立 MT5 Server API 插件，输出 `DynamicLeverageMT5.dll`。源代码使用本仓库原始 SDK API 6182；不依赖其他业务插件。EA/终端脚本不能修改账户杠杆，本实现运行于服务器端。

## 参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `Enabled` | `0` | `1` 启用，`0` 停止调整 |
| `RulesFile` | 空 | 管理端生成的 UTF-8 JSON 的绝对路径，如 `C:\DynamicLeverage\runtime\mt5.rules.json` |
| `Accounts` | 空 | 兼容旧版：逗号分隔账号；与非空 `RulesFile` 互斥 |
| `Tiers` | `0:1000;2:500;5:200` | 仅用于未设置 `RulesFile` 的旧版模式 |
| `PollIntervalMs` | `1000` | 全量账户补扫及配置重读间隔，毫秒 |

v0.2.0 使用本机管理端维护多条组别/账户规则，DLL 只读 JSON。原生 `Enabled=1` 与 JSON 的 `enabled=true` 必须同时满足；文件模式轮询间隔以 JSON 的 `poll_interval_ms` 为准。组别支持 `*`、`ABC*`、`*ABC*`、`!ABC`，逗号分隔，大小写敏感；排除项否决，与排列无关；仅排除项隐含包含其他全部组别。账户使用逗号分隔账号。两种规则统一按列表顺序，第一个启用且命中的规则生效。

按每个账户所有品种的当前持仓累计手数，买卖方向相加，挂单不计入。`IMTPosition::VolumeExt()` 为每手 `100000000` 个整数单位，保留 8 位小数。默认规则：`0–2` 手为 `1:1000`，`>2–5` 手为 `1:500`，`>5` 手为 `1:200`。平仓或减仓后自动回升。Hedging 账户相反方向持仓累计；Netting 账户累计服务器实际净持仓。

启动及每个轮询周期重新读取参数和 JSON。启用组别规则时用 `UserLogins(L"*")` 枚举账号，再逐账户读取组别，由共享匹配器筛选；SDK 数组通过 `Free` 释放，包括返回错误或抛出异常时已分配的数组，仅账户规则无需全服枚举。重复账号、零账号、未设置数量或非空数量缺少数组会使本轮枚举失败；单个用户读取错误独立记录并跳过，枚举或配置整体失败则暂停写入。

持仓与用户新增/迁组事件只合并账号并通知后台单线程处理；不会因每笔交易或自身杠杆更新事件全服扫描。组别模式也接收未进入候选缓存的账户持仓事件，避免新账户在下一次全量扫描前漏掉开平仓。重读配置保留扫描期间到达的事件，全量扫描和单账户事件同时触发时合并去重处理。用户数据库同步通知立即重新发现账户，周期扫描补查漏失事件。JSON 文件丢失、非法或平台不符会暂停写入，不回退旧规则；修复后自动恢复。

仓位 API 失败、部分返回、异常记录不作为空仓。写入前再次读取用户对象并只设置 `Leverage`，期间账户组别或杠杆已变化则等待下一轮。写入前重读 JSON 并检查完整配置签名、原生参数版本和停止信号。日志记录成功调整及错误。停止插件不回滚最近已经应用的杠杆。

极异常情况下若服务器拒绝取消事件订阅，插件停止后台写入但保留事件接收对象，并固定当前 DLL 模块，防止宿主卸载后回调访问失效对象。日志会明确记录失败；可以重试停止，固定的 DLL 需重启服务器进程才会卸载。

## 构建

Windows、Visual Studio C++ x64 工具链、CMake ≥ 3.21：

```powershell
.\scripts\build-windows.ps1 -SdkRoot C:\SDK\mt5-sdk
```

输出在 `build-windows/Release/DynamicLeverageMT5.dll`。核心、测试和 DLL 统一使用静态 CRT `/MT`（Debug 为 `/MTd`）。Windows 原生构建的 CTest 另用 `LoadLibrary` 加载产物并检查 `MTServerAbout`、`MTServerCreate` 导出，检查不会连接交易服务器。将 DLL 通过服务器现有插件部署流程加载，将 `RulesFile` 指向管理端的 `runtime/mt5.rules.json` 绝对路径，清空旧 `Accounts`，确认规则后设置 `Enabled=1`；旧版仅账户参数仍可使用。

跨平台规则/适配器测试：

```sh
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure
```

测试覆盖 gross lots/精度、阈值、账户隔离、失败快照、fresh user 字段保留、Unicode 组别、迁组拒绝旧规则、并发修改、停止/配置变更写入保护、新开户单账户事件合并、扫描期间事件保留、SDK 账户枚举错误/释放/取消及重启。macOS 上的测试不等于 Windows DLL 构建或 MT5 服务器实测。

## 行为边界

插件按已经形成的持仓异步调整账户杠杆，不在成交前按预计持仓拦截订单。持仓变化与用户更新不是服务器原子事务；双快照减少竞争，事件和补扫使账户收敛到新档位。SDK 不提供 compare-and-swap，最后一次配置/用户检查与 `UserUpdate` 之间发生的迁组、管理员修改或文件替换仍可能先完成一次旧写入。账户杠杆对实际保证金的影响取决于服务器及品种计算配置。上线前在演示服务器验证开平仓、跨阈值及保证金变化；不要让多个插件实例同时管理同一账户。
