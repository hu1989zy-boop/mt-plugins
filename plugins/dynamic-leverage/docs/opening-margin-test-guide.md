# 新仓独立保证金：源码与编译测试入口

这次交付是验证源码，尚不是可上线的动态杠杆执行插件。业务口径已确认：按开仓后总持仓选档，整笔新仓采用该档位，旧仓不重新选档。实现方向是保留账户基础杠杆，通过订单保证金比率表达新仓目标杠杆。

## 源码内容与边界

| 内容 | 已完成 | 尚未完成 |
| --- | --- | --- |
| 共享规则 | `quote_opening` 按开仓后持仓选档，继承组别/账户匹配与全局优先级 | 同账号并发预留与成交状态同步 |
| MT4 | 逐单比率转换、原比率/目标杠杆记录、重复处理保护、原始 API 5 类型包装 | 注册到生产交易回调、验证成交前拒单、实际保证金生效和余单持久化 |
| MT5 | 原始订单与改率副本的两次原生保证金检查、返回码和保证金观测；独立只读探针 DLL 源码 | 将新比率写入实际成交、按批次管理净持仓、挂单/网关/日终完整处理 |
| 管理页面 | 配置、优先级与开仓后总持仓试算；显示逐仓执行尚在验证 | 真实服务器执行状态 |

原来修改整个账户杠杆的两个生产执行器已停用。**编译旧名称的 DLL 不会自动启用逐仓执行。** 保留旧代码与测试用于后续改造，不能把旧版账户调杠杆测试通过当作本需求已完成。

## Windows 一次编译两端

准备 Visual Studio 2022 的 C++ 桌面开发工作负载、Win32/x64 工具链、CMake 3.21+，以及已授权的 MT4 Server API 5、MT5 Server API 6182。源码 ZIP 不包含商业 SDK。

解压后的目录应包含 `plugins/dynamic-leverage`。在它的上两级目录（仓库根）运行：

```bat
plugins\dynamic-leverage\scripts\build-opening-margin-validation.cmd -Mt4SdkRoot "D:\SDK\mt4-sdk" -Mt5SdkRoot "D:\SDK\mt5-sdk"
```

只编译一端可加 `-Platform mt4` 或 `-Platform mt5`。默认输出到 `plugins/dynamic-leverage/build-opening-margin`，每次生成新的日志与验证清单；失败时脚本返回非零，不产生本次成功清单。

- MT4：Win32 编译 `MT4DynamicLeverage.dll`，包含新的 SDK 类型包装，但当前启动保护仍阻止旧执行器运行。此步验证编译和静态类型绑定，不是可直接挂载的逐仓插件。
- MT5：x64 编译 `DynamicLeverageMT5MarginProbe.dll`，只对明确指定的一个账户采集订单副本保证金检查结果，真实订单不修改。
- 两端运行 CTest；Windows DLL 加载/导出检查不调用真实 Server API，也不替代 Demo 验收。

本次编写环境为 macOS。上述 Windows 脚本和 DLL 目标未在本机执行；可移植 C++ 构建与测试结果单独记录在 [验收记录](demo-validation.md)。

## Demo 验证顺序

1. [MT5 只读探针](../mt5/probe/README.md)：先检查 `TradeMarginCheck` 是否采纳改率副本。相同账号、相同手数下，分别输出原比率及倍增比率的预计 Margin/FreeMargin，不修改真实交易。
2. [MT4 组件与回调验证](../mt4/order-margin-validation.md)：已提供真实 SDK 包装和测试，交易回调接入仍需要开发。先确认回调顺序、字段保存及缓存生效，再验证实际保证金。不能直接移除启动保护后沿用旧 worker。
3. 在账户基础 1000、无其他保证金调整的简单品种上，验证旧仓 1.5 手加新仓 1 手：旧仓仍为 1000，新仓为 500。比率公式为 `原始比率 × 1000 / 500`，不能把所有品种的原始换算率都当作 1。
4. 验证资金恰好足够基础杠杆、但不足目标杠杆的边界；新仓必须在执行前通过正确的资金检查。之后依次验证重复回调、部分平仓、规则修改、重启、日终、对冲、净持仓和网关成交。

一笔订单字段变成 2，不等于服务器已经按两倍保证金计提；实际账户 Margin、预交易资金检查与重启后的状态都必须一致。当前源码不会通过修改余额、信用或账户杠杆来模拟这些效果。
