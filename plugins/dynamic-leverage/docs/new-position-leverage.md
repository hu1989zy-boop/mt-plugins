# 新仓杠杆与旧仓保留规则

2026-10-14 确认：**规则只决定新增仓位的杠杆，不重新定价已有仓位。跨档按开仓后的账户总持仓选档，整笔新增仓位使用同一档位。**

## 已确认的业务口径

- 组别或账户规则仍按页面顺序匹配，第一条启用且命中的规则决定本次新增仓位档位；各账户独立计仓。
- 原有 1.5 手以 1:1000 开仓，再开 1 手后合计 2.5 手：旧 1.5 手保持 1:1000，整笔新 1 手使用 1:500，不拆档。
- 恰好 2 手属于 1:1000，恰好 5 手属于 1:500；只有严格超过阈值才进入下一档。
- 减仓后回到较高杠杆档位，只影响之后的新增仓位。已有仓位不会升档、降档。
- 修改规则、调整优先级、迁组、停用、重启及维护扫描都不能用当前规则覆盖旧仓的开仓杠杆。
- 部分平仓后剩余仓位继承原杠杆；平仓操作本身不产生新的开仓档位。
- 锁定的是杠杆计算依据，不是永久冻结保证金金额。价格、币种换算、对冲抵扣等仍需遵循平台原生计算规则。

例如，未对冲且其他计算因素不变时，1.5 手的保证金继续使用 1000 作杠杆分母，新增 1 手使用 500；不能把全部 2.5 手统一改为 500。

## 当前实现状态

旧版通过 MT4 `ClientsUserUpdate` / MT5 `UserUpdate` 修改账户杠杆，不能保证上述语义。当前源码已停用这条生产写入路径；两个原生插件在启动工作线程前明确返回不支持的错误，既不启动扫描，也不订阅交易事件。此行为是插件启动失败，不是在交易回调中拒绝客户订单。配置总开关不能绕过该限制。

本地管理、规则排序、通配匹配与离线检查仍可使用。页面“开仓后总持仓”预览只试算新增仓位档位，不代表服务器保证金执行成功。新 `quote_opening` 计算逻辑把 `当前总持仓 - 本次平掉的仓位 + 本次新增仓位` 作为选档依据，返回本次新增仓位的报价结果，不修改账户、旧仓或规则。结果属于离线计算，尚未接入原生交易流程，也不是持久化的仓位锁定记录。

此前的 `0.2.0` 源码包与账户调杠杆验收记录不能作为本需求的可部署交付物。当前 Windows DLL 编译、服务器逐仓保证金执行与真实 Demo 验收均未完成。

## SDK 核对结果

| 平台 | 已确认的接口 | 尚缺少的保证 |
| --- | --- | --- |
| MT4 Server API 5 | 账户杠杆字段；订单 `margin_rate` 是保证金币种到存款币种的换算率；保证金读取和检查接口 | 未找到已说明语义的逐单杠杆/保证金覆盖入口，以及覆盖成交前校验、部分平仓余单、重启恢复的生命周期契约 |
| MT5 Server API 6182 | 浮动保证金配置支持仓量区间、初始/维持保证金乘数，组别引用配置；持仓 `RateMargin` 是币种换算率 | 文档未明确提供按每笔新增量永久锁定的开关或保证金计算回调；不能据此承诺旧仓不受新档位影响 |

本地依据（路径相对于仓库根）：

- `vendor/mt4-sdk/include/MT4ServerAPI.h`：`UserRecord`、`TradeTransInfo`、`TradeRecord::margin_rate`、`TradesMarginCheck` 与导出交易回调。
- `vendor/mt5-sdk/Include/Config/MT5APIConfigLeverage.h`、`MT5APIConfigGroup.h`：浮动杠杆配置结构与组别绑定。
- `vendor/mt5-sdk/Docs/html/imtposition_ratemargin.htm`：明确为保证金币种换算率。
- `vendor/mt5-sdk/Docs/html/imtserverapi_tradeaccountset.htm`：传入账户对象仅使用 Balance 字段，不能当作账户保证金覆盖接口。
- [MetaQuotes 保证金计算说明](https://www.metatrader5.com/en/terminal/help/trading_advanced/margin_forex)：说明按品种计算、币种换算和浮动乘数，没有提供永久锁定每笔开仓杠杆的接口契约。

这些限制不能据以判断逐仓方案不可行。用户提供的 MT4 订单详情显示独立可编辑的“保证金比率”；SDK 的 `TradeRecord::margin_rate` 与利润换算 `conv_rates[2]` 分开存储。MT5 的 `IMTOrder::RateMargin` 文档也明确说明它参与订单保证金计算。当前继续开发并验证这条路径，不以等待供应商文档作为继续开发的前提。

## 逐单保证金比例方案

对于按账户杠杆计算、且订单保证金对该比率线性变化的计算模式，候选公式为：

```text
新仓保证金比率 = 原始保证金币种换算率 × 账户基础杠杆 / 新仓目标杠杆
```

账户基础杠杆保持不变。基础 1000、原始比率 1 时，新仓目标 500 对应比率 2，目标 200 对应比率 5；原始比率为 1.12 时分别是 2.24、5.6，不能直接覆盖成 2、5。旧仓记录保持原值。

必须把原始比率、开仓时选中的杠杆与处理标记保存下来，重复回调或规则重载不能再次乘倍数。MT4 部分平仓余单要继承旧数据。MT5 净持仓加仓要保留原有量的贡献，不能把整个合并后的 position 改成新仓倍数。

SDK 参考：`vendor/mt5-sdk/Docs/html/imtorder_ratemargin.htm`、`imttradesink_hooktraderequestadd.htm` 和 `imtserverapi_trademargincheck.htm`。公开的 [Your Bourse 发布记录](https://www.yourbourse.com/release-notes/mt4-mt5-plugins/mt5-floating-leverage)也明确提到 MT4/MT5 仅作用于新仓的保证金规则。这证明该类功能有实际产品实现，并不证明我们自己的回调、计算和恢复代码已经正确。

原生验证分开检查：字段能否写入、原生预交易检查是否使用它、实际账户保证金是否符合预期、日终和部分平仓是否保留其效果。`RateMargin` 写入成功不能替代这些检查。MT5 日终 `MARGIN_FLAGS_RECALC_RATES` 会重新计算换算率，必须单独处理；目前不修改服务器的该项设置。开发初期先验证简单、使用账户杠杆的品种，再扩展固定保证金、对冲抵扣、净持仓与外部网关成交。

## 原生接入必须解决的事项

1. 下单前保证金检查与成交落地使用同一档位；同一账户并发开单要有明确的排序或预留机制，不能等成交后轮询再调整。
2. 保存并恢复成交时选中的规则版本、杠杆及新增量。重启、规则修改不能重算旧仓；首次启用前已有仓位保留原状。
3. 挂单实际成交、部分成交、MT4 余单、CloseBy、MT5 净持仓加仓/反转必须正确区分平仓量与新增量。净持仓需要按新增批次保存依据，减仓的批次分配口径也需明确。
4. 验证原生可用保证金、预交易拒单与 Stop Out 使用相同计算依据。仅在插件账本记录杠杆不足以完成该要求。
5. 周末或休盘的扫描只做数据核对和恢复，不能对旧仓按当前规则批量重算。维护窗口调度尚未实现。

验收应覆盖：1.5 + 1 手跨档、恰好 2 / 5 手、减仓再开仓、规则修改、并发订单、部分成交、挂单成交、服务重启和 MT5 净持仓反转。必须同时核对旧仓依据不变、新仓保证金正确、账户原始杠杆字段未被插件改写。
