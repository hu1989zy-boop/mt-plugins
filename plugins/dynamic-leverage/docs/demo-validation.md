## 旧版验收流程（已失效，不执行）

MT4 与 MT5 分别执行以下流程。MT4 使用原始 Server API 5 / Win32；MT5 使用 API 6182 / x64；不同 SDK 或服务器版本需再次核对。

1. 使用各平台构建脚本编译 DLL 并运行测试，保留构建日志。先以 `Enabled=0` 装载，管理端总开关也关闭，确认不会修改账户。
2. 启动本机管理端，创建测试规则并保存。DLL 的 `RulesFile` 指向对应平台 JSON 的绝对路径，清空 `Accounts`。分别验证只开一个总开关时均不调整，两者都开启后才调整；页面保存成功不能代替日志中的加载 / 执行确认。
3. 配置组别 `!ABC,*`，建立 ABC、ABCD、real、Real、含反斜杠及中文的组别。确认 ABC 排除、ABCD 可匹配，大小写与路径规则正确；再验证 `!demo*,real*,vip*`、`!ABC`、`*,!ABC`，排除项均否决。
4. 同一账户同时命中组别与账户两条规则，给它们不同档位。在 UI 上移 / 下移、保存后观察日志与实际杠杆，始终采用第一条启用且命中的规则；停用第一条后下一条生效，重启后顺序保留。按组筛选仍逐账户计仓，不汇总整组。
5. 默认三档下：A 依次 0、2、2.01、5、5.01 手，应为 1000、1000、500、500、200；B 始终 1 手应保持 1000。MT5 另测 2.00000001 / 5.00000001 手（若目标品种支持该量步长）。无匹配账户 C 不处理。
6. A 多品种相加，买卖对冲仓位相加；买 3、卖 3 应按 6 手处理。MT5 净持仓按实际剩余 position 计算。部分平仓至 5 / 2 / 0 手依次恢复 500 / 1000 / 1000；挂单不计入，成交后计入。
7. 插件运行期间新开户、迁组、删除 / 恢复用户，确认事件或下一周期及时发现。模拟读取两次快照之间、最新用户复读之前迁组，拒绝旧规则写入；模拟高频开平仓，确保账户最终收敛且没有持续无意义更新。
8. 修改 / 排序规则或关闭总开关时，未开始的旧配置写入应被拒绝。将 JSON 改成非法内容、错误平台、相对路径、重复字段、超大文件或暂时移走文件，应暂停写入而非继续使用旧规则；修复后恢复。分别检查多窗口保存冲突和 Windows DLL 持续读取时的原子替换。
9. 模拟单个账号读取失败、账户更新拒绝，确认记录错误并重试。必须确认 MT4 `OrdersGetOpen` / `ClientsAllUsers` 的失败返回与真实 `null + total=0` 不相同：该 SDK 没有独立错误码，若两者相同，现有实现无法区分，须先解决接口限制才能验收通过。
10. 重启 / 卸载 / 重新装载插件，检查订阅释放、后台线程、错误日志和有仓恢复。关闭或移出规则只停止管理，保留最后杠杆，不恢复启用前值。已进入 SDK 的写入可能先完成一次；SDK 没有原子 compare-and-swap，这一竞态边界需记录。
11. 核对账户杠杆、已用与可用保证金、追加保证金与强平触发行为。不同品种 / 组的保证金计算未必采用账户杠杆，需逐项实测。测量目标规模的周期账户发现开销，再确定 `poll_interval_ms`。
