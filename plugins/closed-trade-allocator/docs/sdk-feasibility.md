# 历史写入接口核查

2026-10-01，核查本仓库已提供的本地 SDK 头文件及 MT5 HTML 文档；未连接服务器、未提交订单、未修改账户。接口语义用于本次源码实现，仍待 Windows / Demo 验收。

## MT4

依据：`vendor/mt4-sdk/include/MT4ServerAPI.h`，行号按本次本地文件记录。

| 接口 | 位置 | 已核实的用途及限制 |
| --- | --- | --- |
| `OrdersGetClosed(...)` | 第 1179 行 | 按时间范围及账号读取已平仓订单 |
| `OrdersAdd(...)` / `OrdersUpdate(..., mode)` | 第 1173～1174 行 | 订单库增改入口；尚未证明能直接插入完整已平仓订单且自动正确结算余额 |
| `RequestsAdd(...)` | 第 1165 行 | 交易请求入口，现有实时跟单使用此类路径；新需求需验证独立历史写入路径 |
| `ClientsChangeBalance(...)` | 第 1160 行 | 余额变更入口，不等同于写入完整订单记录 |

`MtSrvTradesAdd` / `MtSrvTradesUpdate` 属于插件事件回调，不应当作主动写入接口。该头文件的行情历史接口也不代表账号订单历史导入能力。

## MT5

依据：`vendor/mt5-sdk/Include/MT5APIServer.h`，行号按本次本地文件记录。

| 接口 | 位置 | 已核实的用途及限制 |
| --- | --- | --- |
| `DealAdd(IMTDeal*)` | 第 641 行 | 位于 `deals database` 分组，成交库写入入口 |
| `HistoryAdd(IMTOrder*)` | 第 679 行 | 位于 `orders history database` 分组，历史订单库写入入口 |
| `DealPerform(IMTDeal*)` | 第 642 行 | 与 `DealAdd` 分开声明，不能假设与历史写入具有相同副作用 |
| `TradeRequest(IMTRequest*)` | 第 736 行 | 交易请求入口，不能据此保证无市场执行的历史分配 |
| `UserDepositChange(...)` | 第 626 行 | 账户资金变更入口，不等同于写入完整交易历史 |
| `TradeBalanceCheck(...)` | 第 745 行 | `fixflag=0` 只读比较余额与历史，`fixflag=1` 按成交历史校正余额和信用额 |

MT5 历史订单与成交使用不同实体。必须验证合法的订单、成交及 `PositionID` 关联，不能仅新增一条历史订单就宣称 B 已完整获得源交易及其盈亏。

本次进一步读取了 `vendor/mt5-sdk/Docs/html/imtserverapi_dealadd.htm`、`imtserverapi_historyadd.htm` 和 `imtserverapi_tradebalancecheck.htm`：

- `DealAdd` 直接新增历史成交，不改变余额和持仓；票号为零时由服务器生成新票号。
- `HistoryAdd` 新增已结束状态的历史订单，需提供完整的品种、价格、数量及起止时间等字段；零票号由服务器生成。
- `TradeBalanceCheck(1)` 按整个账号的成交历史进行资金校正，不能当作一笔独立的加减余额请求。该操作需要扫描账户历史。

据此，MT5 方案写入成对的历史开平订单和成交，再严格检查目标历史集合、余额差异及信用额；仅在差异可归因于本笔分配时执行一次已持久化意图的资金校正。不另加余额成交，不使用 `DealPerform` 或 `TradeRequest` 模拟历史。此方案要求专用目标账号，禁止并发交易、出入金或其他插件改账；检查与校正不是跨接口事务。

两平台通过 API 专用字段保存来源标记，目标 `Comment` 留空，源 SL/TP 在历史快照及目标记录中保存。不使用备注去重。

## 最小验证目标

指定平台后，使用独立 Demo 账号验证一笔盈利、一笔亏损及含佣金/隔夜利息的完整源交易：

1. 确认接口接受的账号、品种、票号、时间、价格、数量及费用字段，并查明哪些字段由服务器生成或重新计算。B 的标识由目标平台分配，A 的标识作为来源关联保存。
2. 对照写入前后的目标余额、信用额、净值及保证金，核实是否产生持仓、挂单、交易路由或网关事件，确认没有遗留敞口。
3. 从目标历史和报表回查记录集合及资金结果。完整历史写入本身是否改变余额必须先验证，不能直接追加余额调整而造成重复结算。
4. 模拟单次失败、部分记录成功、超时及进程重启，验证目标标记可用于准确回查；不确定结果不得无条件重发。
5. 验证源账号没有被修改，生成的分配记录不会被再次识别为新信号。

只有上述验证通过，才能确认该实现可用于指定服务器 build。若实际接口不能同时满足完整历史与正确资金效果，应将限制反馈到需求层，不能静默把“完整已平仓订单写入”替换成一笔余额调整。
