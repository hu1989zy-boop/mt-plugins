# 平仓订单概率分配需求

状态：需求已确认，2026-10-01 开始 Server API 插件实现。用户补充：不处理部分平仓；写入 SL 和 TP；目标订单不写备注。本文记录首版业务范围，构建与实际服务器验证状态另见 [实现验证记录](implementation-validation.md)。

## 目标与范围

1. 与实时跟单区分，独立存放在 `plugins/closed-trade-allocator/`，独立配置、账本与 DLL。
2. 指定同一平台、同一服务器上的源账号 A 和接收账号 B。MT4 / MT5 分别适配。
3. 源交易完整平仓、历史数据稳定后，按其净盈亏类别进行一次抽样，再决定是否向 B 写入完整已平仓历史。
4. 亏损和盈利概率分别配置。例如亏损 30%、盈利 70%；两者独立，不要求相加为 100%。
5. 入选后按 1:1 写入手数及金额，源 A 的历史记录与资金不变。资金申赎、份额、管理费、跨服路由和持仓跟单不在首版范围。

概率代表一整笔交易是否入选。A 一笔净亏损 100 的交易按 30% 概率入选后，B 承接该笔对应的完整交易与净亏损 100，不是将亏损乘以 30%，也不是每十笔必须分配三笔。

## 首版业务规则

| 项目 | 规则 |
| --- | --- |
| 抽样 | 独立均匀随机数 `u ∈ [0,1)`，严格按 `u < p` 判断；0% 永不入选，100% 全部入选 |
| 盈亏类别 | 已实现净盈亏：利润 + 带符号佣金 + 隔夜利息 + 已归属费用；整个受支持交易的费用只计一次 |
| 持平 | 净盈亏按账户币种精度规范化后为零，跳过且不抽样 |
| 平台/币种 | 同服同币种，保留源品种、手数、方向、开平仓时间和价格；不做币种、品种或金额倍率转换 |
| SL / TP | 复制源历史快照中的 SL、TP，并在目标回查时核对；源值为 0 时保留 0 |
| 备注 | 目标订单、成交 Comment 留空；关联信息使用账本和平台支持的非备注标识 |
| 部分平仓 | 不支持。检测到部分平仓或余单关联即排除，不归并、不按剩余量分配 |
| MT5 交易边界 | 仅支持可明确配对的一笔开仓成交和一笔完整平仓成交；分批开仓、加减仓、反转、Close By 等复杂生命周期排除 |
| 启用边界 | `EnabledSince=0` 时首次启动固化服务器时间；只纳入完整平仓时间严格晚于该边界的交易，同秒保守跳过 |
| 停机补查 | 启用期间普通停机遗漏的完整平仓交易可补查；账本去重 |
| 暂停 | `Enabled=0` 冻结暂停区间，暂停期间及暂停/恢复同秒的平仓均跳过，恢复后不补入 |
| 执行闸门 | `Armed=0` 记录筛选决定、允许结果回查，但不提交目标写入；区别于 `Enabled=0` 的业务暂停 |
| 历史补录 | 默认不处理启用前已平仓历史；不提供绕过去重或清空账本的补录方式 |

部分平仓排除依赖平台实际保留的结构和关联证据。MT4 需要检查部分状态、余单和源历史中的票号关联；这些检查可以读取源 Comment，但不会把备注写入 B。MT5 以 PositionID 查询完整成交集合，不将一组多次平仓拆成多次独立抽样。历史不足、源费用未稳定、无法可靠辨别交易边界时不执行写入。

## 目标历史及资金

入选订单保留源方向、品种、手数、开平仓时间与价格、SL、TP、利润、佣金、隔夜利息及支持的归属费用。B 使用新分配的订单/成交标识；源身份、抽样时间、真实写入进度和目标标识保存在独立账本中。非备注的 API 标识用于目标回查及阻止插件生成记录再次成为信号源。

B 的净余额变化应等于一次分配的净盈亏。历史库写入是否自动产生资金效果属于平台 SDK 的实际行为，必须在指定服务器 Demo 环境验证。不能在未知结果下追加余额调整，以免重复结算；不能用实时开平仓或一笔余额调整替代完整历史。首版适配器要求专用、禁止普通交易且无持仓/挂单的接收账号，以便核对单次资金效果；相关限制及配置见 [部署说明](windows-deployment.md)。

SL/TP 字段保留为历史信息，不应产生新的活动止损、止盈或市场持仓。默认执行闸门关闭；DLL 可编译或加载并不代表历史写入和资金效果已被服务器验证。

## 持久化与故障处理

1. 轮询源历史，并核对完整平仓状态、等待历史稳定和费用归属。重复历史查询复用原决定。
2. 校验源/目标身份、启用/暂停区间、品种和币种，排除部分平仓、非交易记录和本插件生成的记录。
3. 冻结源历史快照、净盈亏、盈亏类别、概率、抽样值、入选结果和持久 API 标记，先落盘后写入目标。
4. 对已入选交易先持久化 `writing`，平台适配器在每一步外部副作用前落盘意图、之后保存目标标识。
5. 回查目标完整记录、SL/TP、空 Comment、关联与资金效果。全部核对通过后才标记 `completed`。
6. 超时、回执丢失、只写入部分记录或资金变化不明，进入 `review` 并只读回查。不盲目重发、补余额或删除记录。

状态为 `skipped → 结束` 或 `selected → writing → completed / review`。只有能明确证明没有任何外部写入的结果，才允许以后再提交同一个任务；一次轮询不连续重试。已提交任务即使暂停或未启用执行闸门也继续核对。

去重身份由平台、服务器、源账号、稳定源交易标识和目标账号组成，不包含当前概率。重复事件、重启、失败重试、修改概率均不得重新抽样；原来未入选的交易也不能重新抽样。已形成决定的任务继续使用冻结的源快照和概率。源历史之后出现修订时保留原快照，记录异常并停止自动补写，不覆盖 B。

每个账本只能由一个运行实例持有。启动时完整校验账本；损坏、截断、身份不符或落盘失败时停止新写入。不得通过删除账本、复制空账本、改用新路径或回滚旧备份重新运行同一关系。

## 配置与查询

每个插件实例配置单条 A → B 关系：服务器身份、源/目标账号、独立账本路径、启用状态、生效时间、执行闸门、亏损概率、盈利概率和历史稳定等待时间。参数名与平台差异见 [部署说明](windows-deployment.md)。

导出/检查结果至少包括源交易、净盈亏、概率、抽样值、入选决定、目标标识、状态与原因。盈利/亏损候选数和入选数分别统计；当前完成数、待写入数与待核对数分开，不能将“入选”当作“写入成功”。首版采用服务器插件参数、TSV 状态报表和日志，无独立图形管理器。

## 验收标准

| 场景 | 预期结果 |
| --- | --- |
| A 尚未平仓 | B 无本插件生成的活动持仓、挂单或历史 |
| 盈利/亏损配置 70%/30% | 各自使用对应概率，短样本不强制配额 |
| 两项均为 0% / 两项均为 100% | 全部不入选 / 全部入选；两项之和不限 |
| 抽样值位于阈值两侧及等于阈值 | 严格按 `u < p` 判断 |
| 毛利润正但净盈亏负 | 使用亏损概率 |
| 净盈亏按币种精度为零 | 跳过且不抽样 |
| 部分平仓及其余单 | 排除，不创建目标分配 |
| SL / TP 为 0 或非 0 | 目标保留源对应值并通过回查，Comment 为空 |
| 重复事件、重启、改概率 | 复用原决定与去重身份，已跳过记录不能再抽样 |
| 写入成功但回执丢失、多条历史仅部分成功 | 读取目标证据，不直接重发完整交易 |
| 写入完成 | 目标完整历史关联、字段、净余额变化均正确且仅发生一次，无遗留持仓；A 不变 |
| 源历史被修订 | 原快照保留，标记 `review`，不自动再次分配 |
| 币种不符、品种不可用或资金效果不符 | 明确失败/待核对原因，不伪报成功、不更改抽样决定 |
| 启用、暂停、恢复、正常停机补查 | 遵守持久化时间边界和暂停区间 |
| 账本占用、损坏、截断或持久化失败 | 拒绝启动/新提交，保留已有写入证据 |

Demo 验收需要分别记录源历史、目标历史与平台报表，以及写入前后的余额、净值、可用保证金、持仓和挂单。平台资金副作用和 Windows Server API 加载均以实际验证记录为准。
