# MT5 0.7.4：合并过期清理与账本计算优化

本版针对 2026-10-14 的 1,200 笔源开仓、10 个跟单账户压测。该次日志中的 864 次开仓拒绝均明确为保证金不足；131 次外部关闭需结合成交 Reason 确认。本版优化持久化开销，不补跟旧拒单，也不改变账户权限、保证金检查或手数规则。

## 改动与兼容

1. **MT5 合并仅由过期防重复记录触发的清理。** 原先源单每约 50ms 出现一个时间点，过期后也可能每约 50ms 触发一次清理并刷盘。现在将滚动 30 秒去重期限的清理截止时间向下对齐到整秒；这个对齐使截止时间最多保守 999ms，多保留一些去重记录；实际清理时刻仍受 worker 调度影响。已有持久化截止时间与订阅启动时间保持单调。已平仓映射的及时释放、容量回收和已确认部分平仓记录整理不等待这个窗口。
2. **加速账本差分和 CRC32。** 使用有界块比较跳过相同字节，保留原来的差分区间合并规则；CRC32 保留相同多项式及结果，优化计算方式。完整校验、每次必要提交后的刷盘以及提交交易请求前的 Prepared 持久化继续执行。
3. **增加诊断字段。** 记录清理提交、仅过期清理、被删除的去重记录和推迟清理次数，以及实际成功提交的帧字节数和未压缩快照字节数。仅改变诊断日志，不写入交易状态。

MT5 账本保持 schema 7、delta frame 4，管理协议保持 2，配置格式不变。旧版账本可以继续读取。MT4 不启用过期清理分桶；共享差分/CRC 计算另做兼容回归。本版没有增加跨平台跟单功能。

## Windows 编译

现场 SDK 路径保持 **`D:\SDK\mt5-sdk`**。将完整源码包解压到独立目录 `D:\work\TradeCopier-MT5-0.7.4`，避免历史工作目录 `D:\work\mt-plugins\plugins\trader-copier\mt5` 内重复嵌套或混用旧源码。新目录下应直接包含 `scripts`、`plugins`、`CMakeLists.txt` 和 `README-WINDOWS.txt`。

在 **x64 Native Tools Command Prompt** 中执行：

```bat
cd /d "D:\work\TradeCopier-MT5-0.7.4"
scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\mt5-sdk" -BuildDirectory "D:\MT5Build\TradeCopier-0.7.4"
```

只有看到 `Build and tests passed` 才使用新产物。输出目录：

```text
D:\MT5Build\TradeCopier-0.7.4\package-executor
```

在独立测试服务器停止 EA、处理完测试仓位、关闭管理界面，并按现有流程停用、卸载旧插件。备份原配置及停止写入后的完整账本和伴随文件，再同步替换 `TradeCopierExecutor.dll`、`TradeCopierManager.exe`、`TradeCopierJournal.exe`。

保留原配置路径、Journal 路径、`ExpectedServerId`、`ApiAppId`、`DealerLogin=2016` 及管理参数。不要删除账本或用示例配置覆盖现场配置。重新加载后检查：

```text
BUILD version=0.7.4 api=6182
```

`build-manifest.json` 应包含 `source_version=0.7.4`、`build_script_revision=27`。源码包不含 SDK 或预编译 Windows DLL/EXE。

## 新增性能字段

仍按有活动的 5 秒窗口输出，普通计数是本窗口增量。

| 日志 | 字段 | 含义 |
| --- | --- | --- |
| PERF | prune_commits | 成功完成持久化的清理提交次数 |
| PERF | prune_expiry_only_commits | 上述提交中，仅处理过期去重记录的次数 |
| PERF | prune_closed_sources_removed | 成功清理提交删除的过期去重记录数量 |
| PERF | prune_expiry_deferred_passes | 遇到已过期记录、但尚未到合并截止时间的清理调用次数；不是订单数 |
| PERF_JOURNAL | committed_frame_bytes | 成功提交的完整帧字节数，包含替换 checkpoint；不含 lease 标记、失败的部分写入或文件系统开销 |
| PERF_JOURNAL | logical_snapshot_bytes | 相同提交若全部按完整快照保存时的帧字节数，包含帧头 |

`prune_commits` 与 `prune_expiry_only_commits` 是包含关系，不能相加。`checkpoint_us` 包含自身的 write/flush 时间；`confirm_us` 包含确认保存时间，仍不能将所有计时相加当作总耗时。`*_max_us_total` 是当前实例生命周期峰值。

先在同一测试服务器用单笔订单验证开仓、部分平仓、全平及反向关系。之后保持本轮参数：源 50001，每笔 0.1 手，目标 20 笔/秒，持仓 10 秒，Buy/Sell 交替，成功开仓上限 1,200。测试账户准备足够保证金，保留保证金检查，避免资金限制降低后半程负载。

达到 1,200 笔后继续运行 EA，让最后的源仓和跟单仓完成平仓与核对。额外保留至少 **35 秒** 日志，以覆盖最后源仓开仓时间之后的 30 秒去重记录过期和清理窗口；不需要保持新开仓。提供完整 `TradeCopierExecutor` 日志和期末实际持仓。既有 2 条映射/1 条意图应在测试前另行核对，不通过删除账本清除。

比较逐账户开平仓数量、实际成交延迟 P95/P99、清理提交次数、提交字节数以及账本阶段耗时。保证金不足、外部关闭与执行错误分别统计。Windows DLL 编译、加载和真实成交性能必须由这轮现场测试验证；本地便携测试与模拟结果不代表 MT5 服务端性能承诺。

## 本地验证

12 组便携测试全部通过，包含 76,888 项执行测试与 369 项新增账本编码测试。新增测试将新版完整帧、差分帧和清理帧与 0.7.3 的参考编码逐字节比较，并覆盖损坏、撕裂写入、错误 base revision、越界 patch 与重启恢复。另有 36,096 项独立编码对比通过 ASan/UBSan。

0.7.3 写入的 Prepared、Submitted、Active 状态均能由 0.7.4 精确恢复，冻结方向和请求序号保留，重启后零重复提交。MT4 共享代码回归通过：runtime 4,084、refusal 60、journal performance 381 项。

仅过期记录场景使用真实本地文件账本和模拟时钟：600 个去重键分布在 60 个每隔 50ms 的源时间点。旧版 60 次清理/刷盘，新版 3 次，减少 95%；最终去重键清空、账本重放一致、重启无重复下单。这一比例只适用于该过期清理场景。

完整模拟使用 1,200 笔源单、每笔 0.1 手、20 笔/秒、持仓 10 秒、Buy/Sell 交替、10 个跟单账户和固定 20ms 模拟成交。模拟中 10 条关系统一使用手数比例 1，没有保证金拒绝；它重现持续开平的压力形态，不重现现场的净值比例、Dealer 或 SDK 历史查询。

按旧版、新版、新版、旧版的顺序串行完成四轮，每轮均完成 12,000 次开仓和 12,000 次平仓，所有仓位清零、账本写入零失败、最终状态精确重放、重启零重复提交。

| 指标 | 0.7.3 两轮 | 0.7.4 两轮 |
| --- | --- | --- |
| 模拟开仓 P99 | 94 / 87 ms | 72 / 73 ms |
| 模拟平仓 P99 | 102 / 87 ms | 61 / 65 ms |
| 账本总耗时 | 44.126 / 43.083 秒 | 32.402 / 32.678 秒 |
| 成功提交次数 | 5,372 / 5,250 | 5,766 / 5,740 |
| 成功提交帧字节数 | 2,491,715,493 / 2,428,809,931 | 2,668,879,664 / 2,665,425,060 |

这两组结果中，账本总耗时下降约 24%–27%，但运行变快后请求分成更小的批次，**整体提交次数和成功提交帧字节数增加约 7%–10%**。现场需要同时观察延迟、提交次数及写入字节，不能仅用过期清理次数的降幅代表整个系统磁盘负载。以上字节数不含 lease 标记和文件系统开销，不代表物理磁盘写入量。

精确结果随源码包保存在 `VALIDATION_STATUS.json` 与 `validation/` 目录。两版使用相同模拟程序；模拟包含真实 macOS 文件持久化，不调用 MT5 API。
