# MT5 Server API DLL 与 Windows 管理界面

当前源码版本 0.4.3，基于用户提供的 Server API 6182。早期普通开平仓及 0.4.0 常规管理流程已有 Demo 证据；0.4.2 带仓修改、开仓规则快照和账本升级通过本地验证，尚待 Windows MSVC / Demo 实测。操作说明见 [带仓修改订阅](frozen-opening-rules.md)。

## 职责

| 组件 | 职责 |
| --- | --- |
| Server API DLL | 观察源成交，按关系计算数量，提交指定目标开平仓，核对实际成交，持久化账本；串行处理管理命令 |
| Windows 管理界面 | 编辑本地草稿；查询执行器状态和生效配置；提交暂停、恢复、暂停新仓后的配置变更（老仓保留开仓规则）；只读核对成交 |
| SDK 无关核心 | 数量计算、关系校验、执行状态机、管理前置条件、账本编码与管理协议 |
| 本机命名管道 | 有界异步 I/O；只允许本机 System / 提升权限管理员；会话与账本版本检查 |

界面关闭、无响应或管理通道断线不会停止已有跟单。原 Administrator 仍负责插件加载、Armed、服务器身份和路径等启动参数。管理界面不是 Administrator 扩展，不依赖第三方 DLL。

## 配置与事务

JSON 使用 schema 2 固定策略；账号、关系 ID、倍率均以十进制字符串保留精度。关系 ID 在修改手数参数时不变，编辑器改变账号组合则创建新 ID 并停用。图校验包含重复组合、自跟单和循环。

管理模式中已有账本保存的 `config_json` 为唯一生效配置，`ConfigPath` 只初始化新账本。应用命令必须满足：执行器健康、新仓已暂停、无待核对映射、所有请求确认，以及进程会话和账本版本仍匹配。服务端验证账户与品种，捕获新的源基线后，通过一次持久化快照提交配置。原映射、成交和意图编号保留；每笔映射的开仓规则保持不变并写入 schema 3 账本；未回写 JSON 文件。界面在收到响应后才显示应用成功；未知结果需重新读取，写命令不自动重发。

0.4.2 支持带仓修改订阅，每笔老映射保留独立开仓规则；仍不支持服务器/品种/应用 ID 迁移，也没有全功能历史配置审计界面。管理开关关闭时保留原来的 ConfigPath 与账本配置严格匹配行为。

## 暂停、恢复和异常

“暂停新仓”会持久化状态，跳过未提交的候选开仓；已提交请求继续核对，已建立映射继续处理实际源平仓。“恢复新仓”先捕获新的源持仓基线、时间和事件序号，防止补跟暂停期间的源开仓。关闭界面不改变暂停状态。

进程重启继续按账本核对映射。未决请求进入 HALTED / REVIEW；停机期间源仓历史变化进入 REVIEW，不自动追平。“核对选中请求”查询带应用标记的订单/成交并返回证据，不变更账本、不补单、不清除停止。人工恢复仍需后续独立设计，不能以一个“清空异常”按钮替代。

## 状态与并发

回调只复制成交事件到有界队列；监听账号集合为不可变共享快照。单个运行线程处理队列、核对交易、应用命令；不同跟单账号最多 32 笔请求同时等待成交，同一账号一次一笔。Prepared 整批先落盘，随后逐笔提交，再合并记录结果。独立回报逐笔核对，正常等待不阻塞其他账号。管理 I/O 不在 MT5 回调上等待。应用规则前切换监听集合，随后捕获基线与队列水位，排除切换边界上的旧事件。源平仓与目标成交（含已退休订阅的在管账号）只唤醒工作线程，借用的 SDK 对象不离开回调；唤醒代次通过短时独立互斥保护，锁内不执行 SDK 或文件 I/O。有在途请求时 50 ms、其他时候 200 ms 轮询兜底。

界面在后台执行通信，定期刷新。展示连接状态、数据年龄、账本版本、在管与待核对数量及最多 200 行映射/请求。断线保留旧表格并标为未知/过期，禁用写按钮。运行数据是执行账本视图，不是账户完整订单查询。

## 访问控制

管道按服务器 ID 与应用 ID 命名，限制首次实例，显式 DACL 只授予 System 和提升权限管理员，拒绝网络登录及远程管道连接。客户端核对管道服务进程身份，不向网络地址发请求。会话令牌与期望账本版本避免重启后误用旧命令或重复应用。

远程管理、普通 Manager 账户权限、账户净值面板、完整日志浏览和有歧义的状态修复不在本版管理接口内。
