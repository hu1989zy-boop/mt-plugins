# 0.5.5：保证金不足按单结算，不阻塞其他账户

> 目录调整：当前 MT5 实现位于 `plugins/trade-copier/mt5/`。本文保留对应版本的源码包和现场路径；在当前仓库复跑命令、查找产物时，请按 [目录与构建入口](../README.md#目录与构建入口) 执行。

## 日常跟单行为

某个账户的开仓被明确拒绝、返回保证金不足且确认零成交时：

- 只结束这笔失败开仓，不暂停全局、不隔离整个账户，不占用在途名额。
- 其他账户继续接收新信号、开仓和跟随平仓。
- 该账户已经成功开出的仓位继续按原冻结规则跟随平仓。
- 下一笔新信号仍可正常尝试；资金恢复后只跟新信号，不补开此前失败的仓位。
- 相同源仓的重复回调不会重复下单。
- 失败请求先持久化为 Rejected，然后释放回调证据；随后从运行账本清理，仅保留短期源仓去重键。完整原因、账号、源仓、品种、请求号及手数写入服务器 REJECTED 日志。

本版本补上 0.5.4 的长期运行缺口：虽然 0.5.4 已识别拒单并避免 30 秒误停，但拒单映射仍为 Review，长期保留会阻挡暂停后的恢复与配置修改，并占用映射容量。0.5.5 将有充分零成交证据的保证金不足开仓标记为已跳过并回收。

这里的“不影响”是指单个明确拒单不会导致其他账户停止、暂停或容量泄漏；共用服务器和磁盘仍存在正常调度开销，不能承诺绝对零毫秒影响。

## 清理条件

必须同时满足：

- 已持久化 Rejected，返回码为 10019，带有效请求号。
- 原因为经过身份验证的 `server_pretrade_no_money_zero_fill`，持久化映射原因精确为 `server_rejected_no_money`。
- 请求为开仓，成交量、成交票号、结果仓位均为空，原请求也没有目标仓位或平仓前数量。
- 映射没有目标仓位、没有目标剩余手数、没有已处理平仓事件，源剩余量仍等于初始量。
- 请求账号、源事件、方向和冻结目标品种与映射一致。
- 该映射只有这一笔请求。

执行器和账本清理验证器使用同一组条件。平仓拒绝、部分成交、结果不明、字段冲突、其他拒绝原因不走此清理路径。真正的结果不明确仍使用原隔离保护；存储或完整性故障仍停止执行。

管理界面以在管/待核对记录为主，已结算资金不足记录可在下一次刷新前被回收。调查此类已结束请求应查看服务器日志，不以运行页永久保存历史。

## 升级边界

0.5.4 中已经明确记录为“零成交保证金不足”的单笔开仓 Review，可以在启动时按上述严格条件回收，保留原来的人工暂停状态。

已有 `HALTED`、未知结果、旧版仅因超时产生的 Review 不会自动清理，也不会据此补平或重发交易。当前事故日志中的 8 笔超时记录不能单凭返回码猜测当成新版本明确拒单。

账本数据结构仍为 schema 5 / delta frame 4，但允许回收的已结束记录种类增加。同步更新执行器、管理程序及账本检查器；新版本写过的账本不应直接用旧版工具读取或降级运行。

## 构建与现场确认

```cmd
scripts\build-windows.cmd -Executor -BuildDirectory build-windows-0.5.5
```

使用现有 Server API 6182 SDK；源码包不包含 SDK。启动日志应同时包含 `0.5.5` 和 `settled no-money openings retired`。

Demo 验收：保留多个账户的旧仓，让其中一个账户新开仓保证金不足；持续发送新信号，再关闭新旧源仓；核对其他账户持续开平仓、资金不足账户的已成交旧仓正常平仓、没有 30 秒全局误停。之后暂停、修改配置、恢复，确认没有已结束拒单记录阻挡。

本地测试命令：

```cmd
ctest --test-dir build-windows-0.5.5 -C Release --output-on-failure
build-windows-0.5.5\Release\tradecopier_execution_tests.exe --routine-no-money-soak
build-windows-0.5.5\Release\tradecopier_execution_tests.exe --no-money-soak
```

`--routine-no-money-soak` 为 10 个订阅账户，1 个账户累计拒单 10,050 次，其他 9 个账户逐轮开平仓，期间修改配置并暂停/恢复，最后测试资金恢复后的新信号。它采用模拟成交和内存账本，验证持续运行和容量回收，不用于衡量 MT5 实际延迟。

`--no-money-soak` 为 1,000 源仓 × 10 订阅账户，8 笔拒单，其余 9,992 笔实际开仓全部跟随平仓，采用真实文件账本。默认回归还覆盖拒单后落盘失败、重启、危险记录不能被清理和真实账本重放。

尚未在用户 Demo 服务器部署。Windows 本机 MSVC 及现场 MT5 回调仍需现场验收。

## 本地验证结果（2026-09-18）

- ASan / UBSan 回归 4/4 组通过；执行器 59,439 项检查，管理界面调度 115 项检查。
- 持续拒单模拟：10 个账户中 1 个账户累计 10,050 次开仓被拒，其余 9 个账户成功开仓 90,450 次、平仓 90,450 次；未全局停止或暂停，未积累待核对记录。逐轮结束后的内存账本快照最大 13,084 字节，此大小不代表真实文件高水位。
- 上述场景中，带有健康账户持仓时修改配置、暂停后恢复均通过；资金恢复后的新源仓可由全部 10 个账户跟随，旧失败源仓没有补开。
- 真实文件账本场景：1,000 个源仓 × 10 个账户，8 笔拒单，9,992 次成功开仓全部完成对应平仓，包含资金不足账户的旧持仓；账本重放一致，已结束拒单全部回收。
- 13 组危险记录清理保护、0.5.4 已知拒单升级、拒单落盘后清理前重启、已有 HALT 保留均通过。落盘失败时仍保留拒单证据并停止执行。
- Windows 程序交叉编译通过；SDK 6182 语法检查通过（使用 MinGW 兼容预包含头，不等同于原生 MSVC 构建）。

真实文件测试耗时 177,536 ms，包含模拟成交、断言和实际磁盘持久化，不能当作 MT5 跟单延迟。
