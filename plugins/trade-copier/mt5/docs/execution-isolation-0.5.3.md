## 确定的设计问题与修正

旧行为：一笔已入队请求在核对阶段超时或返回部分 / 不确定成交，调用全局 `Halt`，所有账号都无法再提交平仓。

0.5.3 行为：

1. 将异常请求及所属映射保留为待核对，**隔离该目标账号**。隔离按账号覆盖全部订阅、全部映射，由完整账本的 Review 请求推导。
2. 全局暂停新仓，跳过尚未提交的候选。保持已经提交的请求继续核对。
3. **其他账号已确认的仓位继续按冻结规则和准确目标票号跟随平仓**。不重新计算老仓的目标品种或开仓参数。
4. 异常账号即使还有其他已确认仓位，也停止新增请求；不会猜测未知成交、自动补单或反向平仓。
5. 隔离和暂停先写入账本，然后才允许其他账号提交平仓。写入失败仍然全局 HALTED。
6. 有待核对执行时，不能恢复新仓或应用配置。迟到的成交可以通过只读核对查看，不自动解除隔离。

本修复针对已明确入队请求的**成交核对异常**。提交调用的未知结果 / 异常、账本写入失败、SDK 查询异常、仓位余量不一致、重复绑定等现有严重保护仍为全局停止。重启遇到未决请求仍为 HALTED；不凭旧错误字符串自动恢复现场账本。

## 诊断变化

`ISOLATED` 行包括：intent、target、operation、request、reason、evidence、evidence_reason、age_ms、requested_ext、filled_ext、position、retcode。

- `execution_confirmation_timeout`：30 秒确认窗口结束，仍没有完整成交证据。
- `partial_execution`：最终证据显示成交量少于请求量。
- `uncertain_execution`：其他无法确认一致性的结果。

SDK 核对附带 `no_matching_order_history`、`order_not_final`、`deal_volume_not_yet_equal_to_final_order` 等具体诊断。只读核对先开始新的读取周期，避免复用上次轮询缓存，并显示目标账号、操作、服务器请求号和证据详情。

字段是证据描述；`no_matching_order_history` 不能据此判定未成交或安全重发。

## 现场处理边界

**不要删除或重建当前事故账本来绕过 HALTED。** 其中保存准确目标仓位、已发送请求及冻结规则；清空后会失去核对依据。

本版不会自动补平现场遗留仓位。先保留日志及账本副本，再核对 9325–9346 的实际结果。需要补充：执行器从这些请求 PREPARED 到 HALTED 的完整片段，以及同时间段 50003 的订单处理记录。部署或重启本身不能解除这次事故。
