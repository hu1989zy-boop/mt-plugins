# MT5 0.7.1：客户只读、服务端跟单

账户 50002 在 0.7.0 出现 `mapping_planning_error: account trading unavailable login=50002`，原因是插件把客户交易限制也作为服务端跟单限制。0.7.1 为只读跟单账户加入服务端代客成交路径；客户权限保持原样。

## 本次确认的环境

- MT5 SDK：`D:\SDK\mt5-sdk`，Server API 6182。
- 代客成交管理账号：**2016**。这是 Manager/Dealer 账号，不是信号源账号。
- 跟单客户：50002，保留 **Enable trading 不勾选**。
- 不需要向插件提供管理账号密码，也不需要为客户勾选 Enable API connections。

## 编译

将新包解压到新的目录，例如 `D:\work\TradeCopier-MT5-0.7.1`，其中应直接看到 `scripts`、`plugins` 和 `README-WINDOWS.txt`。不要把新包的根目录文件混入旧版的内部 `mt5` 子目录。

在 VS 2022/2026 的 **x64 Native Tools Command Prompt** 运行：

```bat
cd /d "D:\work\TradeCopier-MT5-0.7.1"
scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\mt5-sdk" -BuildDirectory "D:\MT5Build\TradeCopier-0.7.1"
```

等待 `Build and tests passed`。本命令明确指定绝对输出位置，成功后的产物目录为：

```text
D:\MT5Build\TradeCopier-0.7.1\package-executor
```

源码包不含 SDK，也不含预编译的 Windows DLL/EXE。

## 加载和参数

1. 先在独立测试服务器操作。关闭管理器，按现有部署流程停用并卸载旧执行器；备份原配置和运行账本。
2. 同步替换编译包中的 `TradeCopierExecutor.dll`、`TradeCopierManager.exe`、`TradeCopierJournal.exe`。保留原配置和账本路径。
3. 在 MT5 Administrator 的该插件参数中新增或修改下列参数，再启用插件：

   | 名称 | 类型 | 值 |
   | --- | --- | --- |
   | `DealerLogin` | **String / 字符串** | `2016` |

   其他原有参数沿用。`DealerLogin` 默认是 `0`，表示尚未配置只读代客成交；旧插件实例通常需要手动添加此参数。该参数在插件启动时读取，修改后需重新加载执行器。
4. 在 Administrator 中检查管理账号 2016：账号启用、有 **Dealer / 交易员** 权限，其允许访问的客户组列表包含 **50002 的实际组名**。插件逐笔复核这些权限；只读客户组未授权时不提交交易。
5. 客户 50002 保持 **Enable trading 未勾选**，打开管理器读取生效配置，再用源账户的新开仓测试。

## 行为和价格

- 客户禁交易/只读时，使用 SDK 的 `TA_DEALER_POS_EXECUTE` 请求，`SourceLogin=2016`、`Login=跟单客户账号`。普通可交易跟单账户沿用原交易路径。
- 插件不调用账户权限修改接口，不临时启用客户交易，不修改客户密码，也不直接修改持仓/成交数据库。
- 按目标账户组调整后的当前报价提交代客成交：实际买入请求取 Ask，卖出请求取 Bid。平仓按实际平仓请求方向选价；报价必须有效且不超过 5 秒。最终成交和拒绝仍以 MT5 返回结果为准。
- 继续检查本服、USD、对冲模式、品种合约、手数、品种买卖方向及成交方式。**不设置跳过保证金检查的标志**。
- 正向、反向以及三种手数模式均适用。部分平仓、全平和退出订阅使用原映射的目标仓位编号。
- 未确认请求不会盲目重发。拒单证据同时核对请求号、账号、操作方向、成交量及代客账号，避免把另一笔请求当成已拒绝。
- 原来两笔待核对记录不会因升级自动补跟，原运行账本保留。升级后用**新的源开仓**验证，不要重复开平历史源单来期待补跟。
- 配置仍是既有 schema 2/3/4，账本仍是 schema 7；本次不增加方向、手数等规则字段。

## 测试服务器验收

1. 使用客户自己的主密码登录 50002，确认手动下单被拒绝；客户终端的 EA 下单也应被拒绝。投资者密码的只读登录不能代替这项检查。
2. 源账户新开 Buy 和 Sell，分别验证正向与反向关系；确认 50002 新持仓的方向、数量、成交价格和来源正确。
3. 源部分平仓、全平，检查只关闭对应跟单持仓；固定手数模式仍等比例部分平仓。
4. 带仓重启插件，检查随后源平仓能关闭原目标持仓；退出订阅按原规则清理目标仓位。
5. 保证金不足测试应拒绝新开仓；管理账号权限/组授权不满足时应在提交前停止。不得因为只读支持放宽这些约束。
6. 再次核对客户 **Enable trading 仍未勾选**，客户端自主下单仍被拒绝。

成功走到只读请求提交前会输出 `READONLY_COPY ... follower=50002 dealer=2016 ... action=200`。这条日志只表示进入提交流程，**不是成交确认**；需结合后续请求结果、真实目标仓位与成交记录判断。

提交前权限、报价等检查失败时记录 `NOT_SUBMITTED ... preflight=...`；未配置参数时会显示 `readonly follower requires configured DealerLogin`。
