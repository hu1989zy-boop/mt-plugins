# 本机管理界面

## 0.7.0 跟单方向

“添加 / 编辑关系”弹窗新增“跟单方向”，新关系默认为正向。正向：源买 → 跟单买，源卖 → 跟单卖；反向：源买 → 跟单卖，源卖 → 跟单买。方向独立于手数方式，每条关系可分别设置。

1. 连接执行器并“读取生效配置”，双击要修改的关系。
2. 选择正向或反向，点击“确定”写入草稿。常规页“方向”列应显示该选择。
3. 点击“应用配置”，核对确认窗口中的方向和参数。保存 JSON 只保存本地文件，不会应用到执行器。
4. 应用成功后读取生效配置，确认方向；之后新开源仓按新方向跟随。原有映射保留开仓方向，修改方向不会主动反手，也不影响源部分 / 全部平仓按映射关闭目标仓位。
5. 运行页“源 → 跟单方向”显示实际方向组合，“开仓规则 / 原因”显示每笔映射冻结的方向。重启后应继续保留这份开仓规则。

旧配置默认正向。本功能需要同步更新执行器 DLL、管理 EXE 和账本工具，不能仅替换管理界面；保留原运行账本。方向与买卖的验证需在 Windows 测试服务器完成，源码自动化测试不能代替实际加载验证。以下章节保留旧版部署历史，当前运行策略仍以 0.6.0 及后续说明为准。

> 目录调整：当前 MT5 实现位于 `plugins/trade-copier/mt5/`。本文保留对应版本的源码包和现场路径；在当前仓库复跑命令、查找产物时，请按 [目录与构建入口](../README.md#目录与构建入口) 执行。

> 0.6.0 已更新运行策略：按映射隔离异常，不自动全局终止；订阅可运行中加入，退出会关闭该关系仓位。新的行为及升级步骤以 [0.6.0 说明](live-subscriptions-0.6.0.md) 为准。

> **0.5.0 历史更新**：新增多品种掩码与自动后缀匹配，当时账本写入 schema 5，保留 10,000 条容量与检查点修复。多品种设置见 [0.5.0 多品种说明](symbol-routing.md)；下文版本记录用于历史参考。

> **Windows 构建更新**：0.4.6 已在用户本机测试发现检查点替换失败，改用 [0.4.7 修复包与构建步骤](windows-checkpoint-fix.md)；下文旧版本命令仅供历史参考。

0.4.6 支持同时在管 10,000 条映射，并同步扩大快照及文件容量保护；需一起更新执行器、界面和账本工具，详见 [10,000 条容量说明](ten-thousand-capacity.md)。

0.4.5 运行页仅保留在管及待核对状态，确认平仓后清理；容量暂停原因显示在运行页和信息页。容量阈值、schema 4 兼容限制和构建步骤见 [运行账本与容量保护](live-state-journal.md)。

0.4.3 执行器支持分账号异步提交及核对，最多 32 个账号各一笔请求在途；运行页“未决请求”可能同时大于 1。部署见 [分账号调度](account-pipeline.md)。

本版将 `TradeCopierManager.exe` 的配置草稿与 `TradeCopierExecutor.dll` 的运行状态连接起来。界面必须运行在同一台 Windows MT5 Trade Server 上；通过远程桌面操作该服务器也可以。它不连接远程 MT5 地址，不使用账户密码，不需要新增 TCP 端口。

最新客户端已按 MT 属性窗口风格重做：常规 / 运行状态 / 信息三个标签页，独立关系编辑弹窗，文件操作合并到“配置文件”菜单；运行页用子标签切换映射和请求，底部“应用配置”对应原“应用草稿到执行器”。包含后台刷新修复。界面布局见 [MT 界面更新说明](manager-mt-ui.md)。**0.4.2 支持带仓新增和修改配置，老映射持久化开仓规则，需要同时更新执行器 DLL、管理 EXE 和账本工具**，见 [带仓修改与更新步骤](frozen-opening-rules.md)；下面的一次性升级步骤针对尚未启用管理通道的环境。

## 已实现

- **配置草稿**：保留三种手数方式、关系编辑、JSON 导入和保存；保存文件不等于应用到执行器。
- **连接 / 刷新**：填服务器 ID 和应用 ID；本轮 Demo 分别是 `1`、`3101`。显示上次响应距今秒数，超过 6 秒标为过期，断线后禁用执行操作。I/O 在界面后台线程，单次交换最多约 8 秒加连接等待。最新客户端源码已区分每 2 秒的后台刷新与用户操作：后台刷新保持符合条件的按钮可用，在途刷新期间接受一次用户操作并串行提交，断线/会话或版本变化则提示未发送；见 [界面刷新修复与更新步骤](manager-refresh-fix.md)，用户 Windows 更新待确认。
- **运行状态**：在管、待核对、未决数量，源/目标票号、余量、请求和实际成交量、返回码及停止原因。列表最多各 200 行，映射优先显示未结束项，请求显示最近项；总数不截断。数量来自账本，不宣称是账户全部持仓或实时净值。
- **读取生效配置**：从执行器响应载入新草稿，提醒处理未保存修改；不根据某个本地 JSON 猜测运行配置。
- **暂停新仓跟随**：暂停状态持久化。尚未提交的候选开仓标为跳过；已经提交的请求继续核对，已有映射继续跟随源平仓。不会主动平仓。
- **恢复新仓跟随**：重新取得源持仓基线、时间及事件序号，只接纳恢复后的新源仓。暂停期间的源仓不补跟；HALTED 或有待核对映射时拒绝恢复。
- **应用草稿到执行器**：必须先暂停，所有请求已确认且无待核对映射。允许保留正常持仓并新增、修改、停用或删除订阅；老映射保留独立开仓规则，后续新仓使用新配置。执行端再次验证 JSON、关系图、账户及品种条件；一次账本快照提交新配置并保留在管状态和请求编号。成功后仍暂停，用户检查后再恢复。
- **核对选中请求（只读）**：重新查询带程序标记的订单/成交，显示完整、拒绝、等待或不确定结果。不会改写映射、解除 HALTED、补单或重发。这是异常诊断入口；有歧义的交易仍需人工处理，尚无自动修复按钮。

## 一次性升级（Demo）

1. 在旧版界面 / Administrator 确认当前测试已经结束。停用 `TradeCopierExecutor`，等待日志 `plugin shutdown finished`。备份当前 DLL、EXE、配置和**原运行账本**；不要清空账本。
2. 在 Windows 的 x64 Native Tools Command Prompt 编译：

   ```cmd
   cd /d "D:\work\mt-plugins"
   scripts\build-windows.cmd -Executor
   ```

   新文件在 `D:\work\mt-plugins\build-windows\package-executor`。这一步只编译和测试，不安装、不启动服务、不交易。Windows 管道集成测试需要管理员权限；普通权限运行会显示跳过。

3. 替换服务器插件目录中的 `TradeCopierExecutor.dll`，以及 `D:\MT5Copier` 中的 `TradeCopierManager.exe`、`TradeCopierJournal.exe`。DLL 被服务锁定时，在 Demo 的维护窗口停止对应 `mt5tmsrv` 服务后替换，再启动；不要复制到其他服务目录。
4. 在 Administrator 的该插件参数中增加 **Integer `ManagementEnabled` = `1`**。保留原来的 `Armed=1`、`ExpectedServerId`（String）`1`、`ApiAppId=3101`、`AllowedSymbol=XAUUSDp`、ConfigPath 和 JournalPath。本轮原账本为：

   ```text
   D:\MT5Copier\runtime\executor-two-to-one.journal
   ```

   管理通道默认关闭；`Armed=0` 时也不创建通道。首次启用管理通道不会自动暂停已有配置，执行器仍按原状态运行。
5. 启用插件。以**管理员身份**启动 `D:\MT5Copier\TradeCopierManager.exe`，服务器 ID 填 `1`，应用 ID 填 `3101`，点击“连接 / 刷新”。确认身份、原账本路径、运行状态。
6. 点击“读取生效配置”。应看到原来的 `50001 → 50002`（比例 1）和 `50003 → 50002`（固定 0.02）；以执行器实际返回为准。

### 账本兼容与配置来源

- 当前 0.4.5 写入 schema 4，持久化在管映射的开仓规则、独立请求编号和去重门槛；自动读取 schema 1 / 2 / 3。请同步更新三个程序；不能通过回拷旧账本降级。

- 升级前保留程序和账本副本；运行产生新交易后不能用旧备份覆盖新账本来降级。
- `ManagementEnabled=0` 保留“ConfigPath 必须与账本配置一致”的原校验。
- `ManagementEnabled=1` 时，已有账本里的配置是运行配置的唯一来源。ConfigPath 仅在没有账本记录时用于初始导入；修改或保存 JSON 不会自动改变运行配置。管理界面应用后不会反写初始 JSON，需“读取生效配置 → 另存为”导出备份。
- 服务器身份仍必须一致；损坏账本或未知请求不会被管理开关绕过。新配置、暂停/恢复命令必须匹配当前进程会话和账本版本，旧界面快照或重放请求会被拒绝。
- 应用返回超时只表示结果未知。重新连接并读取生效配置/暂停状态核对；客户端不会自动重试写命令。

## 管理验收步骤

2026-09-16 本轮常规 Demo 流程通过：连接与配置应用/读回、暂停/恢复不补跟、新仓开平、有持仓暂停时的应用入口保护和继续平仓、插件重新启用保留状态、正常平仓请求只读核对，以及已有关闭历史时应用配置。收尾已将 50001 → 50002 恢复为 1:1，50003 → 50002 仍固定 0.02 手；当前为暂停、账本版本 25、2 条已关闭映射及 4 条已确认请求。截图范围、用户确认依据和剩余项目详见 [验收记录](windows-build-validation.md)。下列清单包含尚未实测的异常、并发与故障场景，不表示所有条目均已通过：

1. 连接旧 DLL、未开管理参数、非管理员运行：连接应失败，不能显示“已生效”。正确连接后核对原关系、路径和历史请求。
2. 读取配置但不编辑、不应用，检查所有账号、模式、参数与原规则一致。关闭界面再打开，跟单执行不依赖界面进程。
3. 无在管仓位时暂停新仓。检查界面和执行器确认；停用/启用插件后仍应暂停。确认原账本和历史编号未丢失。
4. 暂停时在源 Demo 开一笔小仓，目标不应补开；保持源仓存在后恢复，仍不补跟。结束这笔测试，再开新的源仓，应正常跟随。
5. 0.4.2：已有正常持仓时暂停并修改手数，应用不应触发调仓；检查后恢复，新仓使用新配置，老仓仍按开仓规则部分 / 全部平仓。重启与删除订阅后，老映射应继续管理原目标票号。新增行为待 Demo 实测。
6. 应用完成后正常重启插件：从原账本恢复新配置；修改初始 JSON 不得覆盖已生效配置。
7. 在两个界面并发操作或断开连接：旧版本命令应拒绝，断线显示状态未知，无自动重发。选中历史请求只读核对，不应新增交易请求。
8. HALTED / REVIEW 场景使用隔离 Demo 测试准备，不手工破坏当前账本。界面必须展示原因并禁止绕过停止；异常恢复仍按人工核对流程处理。

## 通道实现与验证边界

本地命名管道 `\\.\pipe\TradeCopier.Management.v1.<server>.<app>` 使用显式 DACL，只允许 System 和提升权限的管理员，拒绝网络登录与远程客户端；客户端验证管道服务端进程身份。命令处理与跟单在同一执行线程串行执行，I/O 使用有超时、可取消的 overlapped 操作，不在 MT5 回调里处理 UI 请求。

依据：[Microsoft 命名管道权限](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)、[异步管道服务端](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-server-using-overlapped-i-o)。

本地核心测试覆盖暂停/恢复边界、候选跳过、已提交请求核对、已有平仓继续、配置切换保护、账本重启、旧 schema 兼容、64 位协议值、畸形消息和只读核对。Windows 另提供管道集成测试，检查完整大响应、重复实例拒绝、半包断线后重新连接与取消 I/O。Demo 常规流程依据用户截图和明确确认完成验收，包括带关闭历史的配置应用；本版 MSVC 构建输出、独立管道运行测试及异常、并发、故障等场景仍需单独验证。
