# 0.5.2：清理旧压测遗留记录，恢复按钮状态

> 目录调整：当前 MT5 实现位于 `plugins/trade-copier/mt5/`。本文保留对应版本的源码包和现场路径；在当前仓库复跑命令、查找产物时，请按 [目录与构建入口](../README.md#目录与构建入口) 执行。

## 原因

旧版 0.4.7 把“源仓已经关闭、且尚未发出跟单请求”的候选标为待核对。此前日志中有 680 个源仓 × 2 个订阅，共 1,360 条这类记录。0.5.1 已修正新候选的处理，但没有迁移账本里已有的待核对记录，因此“在管 0、未决请求 0”时仍可能无法恢复。

管理界面的“暂停”按钮在已暂停时禁用；“恢复”和“应用配置”则被这些待核对记录阻止。自动状态刷新不会将后台轮询视为操作忙碌。

## 清理范围

执行器启动时仅清理同时满足以下条件的记录：

- 状态为待核对，原因精确等于 `source_opening_predates_activation_or_already_closed` 或 `source_opening_expired`。
- 没有任何关联交易请求，包括已准备、已提交、已确认、被拒绝和待核对请求。
- 源初始量、源余量、目标余量、目标仓位号均为零，没有处理过任何源平仓。
- 执行器没有 HALTED 原因。

这些旧分支发生在规划跟单请求之前。清理依据是完整账本中的“从未提交”证据；**目标仓位号为零本身不能作为清理依据**。其他待核对记录和真实未决交易继续保留。

先持久化“跳过”状态，再通过原有清理机制移除记录；任一步写盘失败就停止启动，不发送交易。重启可继续完成中断的清理。当前订阅配置、递增请求编号和暂停状态均保留；不会补开旧仓、自动恢复跟随或修改 MT5 账户历史。

这里清理的是跟单账本的运行记录。已结束记录从当前逻辑状态移除；文件中的旧帧仍按原有 64 MiB / 256 条追加记录检查点规则替换，空仓超过 8 MiB 时收缩。无需删除整份账本。

运行页新增持续显示的操作条件；选中映射后，下方显示其原因及冻结的开仓规则，不必横向滚动寻找原因列。

## 构建、更新、恢复

本次用户已确认所有持仓已手动平掉。停止压测 EA，并在 Demo 上执行：

1. 在源码目录使用 x64 Native Tools 命令提示符构建：

   ```cmd
   scripts\build-windows.cmd -Executor -BuildDirectory build-windows-0.5.2
   ```

   SDK 不在 `vendor\mt5-sdk` 时加上 `-SdkRoot "实际 SDK 目录"`。源码包不含 SDK。

2. 停用 `TradeCopierExecutor`，关闭旧管理界面，备份运行目录。使用构建输出 `package-executor` 中的 `TradeCopierExecutor.dll`、`TradeCopierManager.exe`、`TradeCopierJournal.exe` 更新对应文件。保留原 `executor-two-to-one.journal`、配置和插件参数。
3. 重新启用插件，确认启动版本为 **0.5.2**。符合条件的记录会在启动时清理，成功后日志出现：

   ```text
   MIGRATION cleared_legacy_unsubmitted_reviews=1360; openings_paused=1; no trade requests sent
   ```

   数量以实际账本为准。如果仍有待核对记录，选中映射查看原因；本版不会强制清掉其他异常记录。
4. 打开新管理界面并连接。若只剩这批旧记录，清理后显示“在管 0、待核对 0、未决请求 0”，保持“新仓已暂停”，“恢复新仓跟随”可用。
5. 读取生效配置，确认订阅正确后点击“恢复新仓跟随”。后续只跟新的源开仓。

本版沿用 schema 5、管理协议 v1，以及 0.5.1 的增量账本格式。兼容 0.4.7 和 0.5.1 账本；写入新帧后，旧于 0.5.1 的程序不能读取。

## 验证范围

新增真实 schema 4 文件恢复用例：1,360 条旧记录、清理后重新读取及第二次重启、配置和请求编号保留、恢复后不补旧仓。覆盖任意关联请求状态、非零执行进度、未知原因和 HALTED 不被误清理，以及两处写盘失败后的恢复。管理界面逻辑验证禁用原因不被普通刷新结果覆盖。

本地 ASan / UBSan 回归 **4 / 4 通过**，执行器测试 47,542 项检查，界面调度及提示测试 115 项检查；Windows 管理界面、账本检查器及测试程序交叉构建通过，Server API 6182 语法检查通过。原始结果位于 `out/validation-0.5.2`。

当前环境不能执行 Windows 原生界面、MSVC 构建或连接你的 Demo；实际账本清理在部署新版并启用插件时发生。0.5.1 的 10 账号定时压测程序与热路径调度保持原样，本次新增启动清理和管理界面回归，没有把旧压测结果当作新版本现场实测。
