# 0.5.1：批量跟单调度与增量账本

> 目录调整：当前 MT5 实现位于 `plugins/trade-copier/mt5/`。本文保留对应版本的源码包和现场路径；在当前仓库复跑命令、查找产物时，请按 [目录与构建入口](../README.md#目录与构建入口) 执行。

修复 0.4.7 压测暴露的排队问题，并保留 0.5.0 的多品种、后缀匹配、老仓冻结配置及 10,000 条在管映射容量。

## 改动

- **按仓位串行，按账号有界并发**：同一账号最多 8 笔在途请求，全局最多 128 笔。不同仓位可以同时等待成交；同一仓位必须确认开仓后才能平仓，部分平仓也逐次确认。128 是请求数量限制，不是账号数量限制。
- **先确认，再接收新仓**：每轮先核对已提交请求，最多接收 32 个源开仓回调，再处理开平仓；不再先连续处理 4,096 个新仓回调。工作线程仍只有一个，SDK 调用没有改成多线程。
- **合并持久化**：本轮尚未提交的候选和开、平仓 Prepared 一起写入并同步刷盘，之后才发送本批请求；提交结果再合并刷盘。候选尚未落盘前没有任何交易副作用。重启以新的启用基线跳过这些未提交源仓，不补单。
- **公平处理开、平仓**：优先规划已有仓位平仓，同时在有新仓排队时限制单账号平仓占用的并发位。每个规划阶段最多处理 1,024 条映射或用时约 5 ms；单次 SDK 调用不能被这个预算中途打断。工作线程空等兜底缩短到 10 ms，实际延迟还包括 SDK、刷盘和扫描时间。
- **修正轮询游标**：清理已平仓记录后，按下一条仍在管的映射继续；跳过暂时占满并发位的账号时，不会把游标绕回原处、反复跳过较早候选。
- **分组保存未提交结果**：源交易已经关闭或过期、且尚未提交跟单请求的候选记为跳过并清理，不再逐条 REVIEW、逐条保存全量状态。无效证据、未知成交和已提交异常仍保留待核对/停止保护。
- **共享历史查询**：同一读取周期内复用账号的成交/订单历史窗口；下一周期清空。每类缓存最多 32 个账号、总计 100,000 行，单次查询超过原有行数限制仍停止而非截断证据。
- **增量账本**：小变更写入带校验的字节范围差分，清理已平仓状态通过可重放记录完成，不再每次清理都替换文件。写入前直接校验内存状态，取消“完整编码后立即完整解析”的重复分配。仍保留完整状态编码和清理时的验证开销，不声称所有工作都与变更条数成正比。

批次内的平仓请求排在开仓请求之前，但整个批次仍需完成规划和 Prepared 刷盘；一个慢 SDK 查询或慢刷盘会影响该批次。单个账号的未知结果仍会停止新请求，不会自动重试或越过未决结果。

## 文件大小与恢复

| 项目 | 行为 |
| --- | --- |
| 主文件 | 默认在超过 64 MiB 前替换为完整检查点 |
| 恢复工作量 | 最多追加 256 条记录后生成检查点，避免小差分无限累积拖慢启动 |
| 单快照 | 硬上限 32 MiB；16 MiB 起保护新开仓并预留空间 |
| 磁盘余量 | 低于 256 MiB 暂停新仓，已有平仓继续管理 |
| 已平仓订单 | 从当前逻辑状态移除；只保留短期去重键，不永久累积历史订单 |
| 旧帧 | 在下一次文件替换前可能仍存在于主文件中，总量受主文件阈值约束 |
| 空仓收缩 | 清理时主文件超过 8 MiB 且无映射/请求，主动生成小检查点 |
| 临时文件 | 替换期间会同时存在主文件和一个检查点临时文件；不生成滚动归档 |

状态 payload 仍是 schema 5，新增 `TCXJ0003` 清理帧、`TCXJ0004` 差分帧。差分包含前一版本号、重建后长度及校验和，外层帧也有校验和。恢复按顺序重建并验证状态；损坏、截断、版本错配或非法清理都拒绝加载，不回退到旧快照悄悄重发交易。

**新帧写入后需要 0.5.1 或更新版本读取，不可只把 DLL 换回旧版。** 一起更新执行器、管理界面及账本检查器。已提交但结果未定的请求仍会在重启后停止并要求核对。

## 日志定位

`PREPARED` 增加：`source_login`、`source_position`、`source_deal`、`source_event_ms`、`source_open_ms`、`queue_age_ms`。其中平仓的 `queue_age_ms` 从对应源平仓成交时间开始计算，开仓从源开仓回调时间开始计算。结合 `intent`、`CONFIRMED target_position` 和账号成交日志，可以逐单关联源、目标，而不必依靠均值倒推。

`BATCH` 保留规划、Prepared 刷盘、SDK 提交及结果刷盘耗时。入队时间不等于实际成交时间。

## 10 个跟单账号的模拟

场景：每秒 30 个源开仓、共 1,000 个源仓，每个持仓 10 秒；每个源仓跟到 10 个账号，预期 **10,000 次目标开仓 + 10,000 次目标平仓**。

使用单调时钟真实定时、实际 `Engine` 和实际 `FileJournal` 文件写入；模拟服务器在提交后 20 ms 异步成交。源仓按独立时间表开平仓，工作线程阻塞不会把源事件时间一起推迟。每笔请求验证 Prepared 已完成持久化；逐源、逐账号检查重复、成交量、最终持仓及重启不重发。

运行两种条件：本机实际刷盘；每次实际刷盘额外增加 5 ms。原始结果保存 `summary.json`、`trades.jsonl`、`executor.log` 和 `recovery.txt`。差分缩小文件写入量，但同时在管状态较大时仍有编码、比较和校验成本。

本地结果见 [定时压测报告](throughput-0.5.1-results.md)；原始证据保存在仓库的 `out/analysis/stress-10-followers-0.5.1` 和 `out/validation-0.5.1`。这些是 **macOS 模拟结果，不是 Windows / MT5 Demo 的实测承诺**；模拟未包含真实报价、保证金、成交路由及完整 SDK 历史查询成本。Windows 文件替换、MT5 实际成交时序和最终延迟仍需在 Demo 复跑。

## Windows 构建与复跑

在 x64 Native Tools 命令提示符运行：

```cmd
cd /d "D:\work\mt-plugins"
scripts\build-windows.cmd -Executor -BuildDirectory build-windows-0.5.1
```

源码包不包含 SDK。若不在默认 `vendor\mt5-sdk` 目录，指定实际目录：

```cmd
scripts\build-windows.cmd -Executor -SdkRoot "D:\SDK\mt5-sdk" -BuildDirectory build-windows-0.5.1
```

构建脚本会运行回归测试；43 秒以上的定时压测需另外运行，输出目录必须不存在：

```cmd
build-windows-0.5.1\Release\tradecopier_stress_simulation.exe "D:\MT5Copier\stress-0.5.1-native" 0 20
build-windows-0.5.1\Release\tradecopier_stress_simulation.exe "D:\MT5Copier\stress-0.5.1-slow" 5 20
```

这个诊断程序使用自建模拟账号和独立账本，不连接 MT5，也不操作实际持仓。不能把真实运行账本放进测试目录。

另可运行原有 10,000 条在管容量及恢复检查：

```cmd
build-windows-0.5.1\Release\tradecopier_execution_tests.exe --capacity-soak
```

部署时停止压测 EA、暂停新仓并等未决请求归零；备份运行目录，停用插件后更新 `package-executor` 中的 DLL、管理 EXE 和检查器。保留原 `executor-two-to-one.journal`、`.lock`、配置和插件参数。升级期间源仓不能变化；已有仓位可保留，但未决或离线变动仍按恢复保护核对。启用后确认启动行包含 `0.5.1`、`max-inflight=128`、`per-account=8`、`incremental journal frame=4`，再恢复并在 Demo 复跑原 EA 场景。
